# #1010 qualification plan: one explicitly chosen OpenClaw conversation

Decision: NARROW. SOL medium may add bounded injectable seams, ownership tests and an internal qualification runbook. Keep SHOW_OPENCLAW_TAB default-off and all HardwareTriggerDestination cases unchanged. No Action Button agent destination, persisted sticky route, reply notifications, lock-screen transcript preview, new recorder or automatic retry. A successful foreground conversation is not proof of the proposed background product.

## Existing path and concrete risk

Inspect Sources/SpeakiOS/Services/OpenClawChatCoordinator.swift and OpenClawChatCoordinator+HandsFree.swift. sendTextMessage captures a conversation before ensureConversationReady finishes, then stores a user message and requests client.sendMessage with its sessionKey. The acknowledgment later sets mutable currentRunId. Delta/final/error callbacks compare run IDs, but persistAssistantMessageIfNeeded chooses mutable currentConversation; selecting another conversation or receiving an old acknowledgment can therefore cross ownership boundaries unless explicitly fenced. stopAllAndDisconnect and cancelVoiceInput need qualification independently of a successful network send.

Reuse this coordinator/client/store and existing capture completion identity. Do not add a second recording service. OpenClawActivityManager currently publishes status/title/count/duration through local updates with pushType nil; it has no background push-delivery or reply-preview contract. Leave that payload intact. A 30-second background allowance is not guaranteed; Apple describes finite execution with expiration handlers, not a fixed service SLA: [Extending background execution](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time). Record OS/toolchain and actual elapsed behavior instead of adding speculative future-OS APIs.

## Bounded executable seam and tests

Add an internal testable dependency initializer to OpenClawChatCoordinator, retaining public init() as a production forwarding initializer. Inject only connection/send callbacks, conversation-store operations, clock and TTS/activity effects needed by tests. A narrow internal transport adapter over OpenClawClient is appropriate if closures cannot express callback registration clearly. Do not refactor app-wide injection or every OpenClaw type. Existing concrete production defaults remain the same; isolated tests must not contact the gateway or real singleton store.

Model a qualification operation with generation, captureRunID, conversation UUID/sessionKey, explicit send consent, expiration and eventual gateway runID. This is an ephemeral internal operation for a selected conversation, not a persisted capture destination or global Action Button lease. Construct it only from a deliberate send in the internal flow. Freeze conversation identity before awaiting readiness and revalidate generation/consent/expiry after every await and delayed acknowledgment. Expiry is an injected qualification parameter, documented as test policy rather than a measured background budget. Ordinary dictation has no operation and cannot send.

First add deterministic tests reproducing the existing risky timing: connection blocked then conversation switched; send acknowledgment after cancellation; old acknowledgment after a newer request; final/delta/error for an old run; same message text in different runs; final after expiry; capture result arrives after scope expiry; duplicate final callback. Assert zero unauthorized sends, no messages attached to another conversation, no stale TTS/resume/activity update and no duplicate agent action.

Any narrow ownership correction needed to make the existing internal path satisfy these tests should be isolated and reviewed explicitly: bind accepted gateway run to the frozen conversation, invalidate generation at cancel/disconnect/switch, and persist response only into that bound conversation while it remains valid. Do not silently revive an expired operation to use a newer selected conversation. Preserve valid streamed-segment behavior; deduplicating identical text globally is not a substitute for run/segment identity. If fixing production semantics grows beyond this seam, publish the failing trace and propose a separate scoped change rather than using this qualification issue for a conversation rewrite.

Keep original final capture recoverable through the existing History path before any permitted send. A test harness receives an identified finalized capture result, never SharedTranscriptionState’s mutable “latest” value, and verifies durability/ownership before forwarding it to the same coordinator method. If current voice-chat capture intentionally bypasses dictation History, record that gap and use a separately finalized ordinary capture for this qualification; do not claim chat-store persistence equals History recovery. No #1009 spoken command activates agent sending.

Use a controllable fake gateway/client plus isolated store for model tests in Tests/SpeakiOSTests/OpenClawConversationOwnershipTests.swift. Keep OpenClawConnectionTesterTests and core OpenClawTypesTests/ContentExtractionTests. Include cancellation before and after network acceptance: once the service accepted a message, local cancellation cannot promise reversal of external agent actions. A timeout with uncertain acceptance is “unknown”, never an automatic retry. Preserve #996’s safe user-facing errors; no gateway body, URL/token or transcript in logs.

## Internal device runbook

Create Docs/openclaw-conversation-qualification.md with prerequisites, exact steps and a results table. Native code can be drafted on Linux, but execution needs an authorized internal iPhone build, existing configured gateway/account, approved non-sensitive fixture and explicit per-run send consent. Use a gateway conversation configured to avoid real external actions. If no such environment is available, record the missing gateway/device/consent gate and stop network execution. Do not create accounts, enable billing or send agent messages under ordinary dictation authorization.

Test foreground send first, then start the same explicitly chosen send through the current internal coordinator and background/lock the phone. Record acknowledgment, first/final reply and persistence separately. This qualifies an initiated internal send; it does not demonstrate cold locked Action Button start. Include connection failure, interrupted capture, canceled finalization, conversation switch, scope expiry before send/after acknowledgment, denied notifications, app suspension, termination and relaunch. Assert the next ordinary capture returns to normal dictation and an expired conversation never receives it. Recovered uncertain sends must remain manual decisions with original History retained.

Transcript-send consent and reply-preview consent are separate. This increment sends only an explicitly selected synthetic transcript and keeps reply previews off; verify no raw reply is inserted into Live Activity payloads or notifications. Permission to show notifications is not permission to reveal reply text. With notifications denied, report which existing in-app/status result survives; do not add a notification fallback to make the test pass. Positive preview delivery remains a future gated feature, not a missing implementation in this scope.

For each scenario record build/OS/device, initial app/lock/connectivity state, synthetic capture and conversation identifiers, consent/expiry state, send count, acknowledgment/result disposition, destination History ID and redacted failure. Do not publish session keys, account details, transcript or raw gateway traces. Native lint/build/affected tests establish the seam; actual suspension/termination and locked-phone behavior require device evidence. Neither UI animation nor a local Activity update proves remote reply delivery.

Finish with a qualification result and explicit next product decision. Until background behavior, identity and expiry are demonstrated, keep production flags and destinations unchanged. No new lock-screen preview, notification action, scheduled background task, Watch transport, release dispatch or Stable promotion is authorized.
