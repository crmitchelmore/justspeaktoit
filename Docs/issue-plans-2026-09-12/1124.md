# #1124 implementation plan: scoped ordinary HTTP test fixtures

Decision: NARROW; SOL medium. Share complete-response/throwing request fixtures across a bounded set of tests. Existing cancellation, partial-response and deferred-completion protocols remain. The ticket's '31 identical copies' and exactly-one-subclass goals are not acceptance requirements. Read reviews/1124.json and current test-support changes, including #1130's live WebSocket fake; do not merge HTTP and WebSocket test architectures.

## Test-only target and supported contract

Add `Tests/SpeakTestSupport/StubHTTPSession.swift` in a `SpeakTestSupport` regular target, Foundation-only with no XCTest import. Add a library product only if Tuist needs `.package(product: "SpeakTestSupport")`; do not link it to shipping products. Add dependencies only to migrated test targets initially and to Tuist SpeakiOSTests. Verify Project.swift sources do not accidentally compile the support files into app/UI fixture bundles. Preserve #1120 isolated benchmark test graph; it has no HTTP need.

Use instance-owned fixtures, for example `StubHTTPSession(handler:)` exposing session, capturedRequests and close/reset-for-this-instance. Handler is `@Sendable (CapturedHTTPRequest) async throws -> StubHTTPResponse`, where the captured value contains the normalised URLRequest and immutable body Data; response contains HTTPURLResponse and complete Data. Synchronous closures can trivially adapt. Handler throwing means fail the request. Missing handler fails promptly and visibly; no implicit real-network fallback. There is no nil tuple/hang mode in this first contract. Provider-specific JSON/headers/assertions stay in tests.

Instance ownership alone does not associate a URLProtocol invocation with its originating URLSession. Before migrating, prove a native session-identification seam for requests constructed inside provider code. Do not rely on URLProtocol.property magically propagating from configuration (it does not set properties on new requests), a process-global current handler, URL matching, or injected URL/header markers that change request-contract assertions.

A bounded implementation option is one protocol subclass identity per fixture/session, registered by a tiny Objective-C-runtime-backed factory and mapped under a lock to its fixture state. Configure only that class in that session's protocolClasses. The subclass inherits ordinary loading behaviour; identity selects state without altering request bytes/URL/headers. Validate inherited callback dispatch/canInit and identity on Apple before adopting this option. Keep registered classes alive for the test process because Foundation may retain them; release fixture handlers/records on close and never recycle an identity while requests remain. Do not grow a general mocking DSL or use class disposal tricks. If native runtime subclassing is unsuitable, choose another demonstrated per-session seam with the same no-request-mutation requirements; keep existing fixtures until that proof exists. A shared global handler is not an acceptable fallback.

Use the fixture lock for handler/record list snapshots and per-protocol stopped state; call user handlers/URLProtocolClient outside locks. Store the spawned handler Task and cancel it in stopLoading. Suppress completion/data/failure callbacks after stop, including a handler ignoring cancellation. Terminal delivery is once. These are ordinary request-lifecycle safeguards, not a reason to migrate specialised delayed/hanging fixtures prematurely.

Read an incoming httpBodyStream once into Data, preserve empty versus missing body appropriately, and give both handler and recorded assertions the same bytes. Handle negative stream reads/errors, close streams, and do not redrain in a convenience `body` function. For #1114 from-file multipart uploads, preserve actual body assertions through the upload seam/native Foundation delivery mechanism; do not synthesise a body from expected fields or drop checks because httpBody is nil.

## First bounded migration

Migrate representative ordinary fixtures only after support-contract tests pass:

1. SpeakApp `OpenAITranscriptionProviderTests` and `GroqTranscriptionProviderTests`: preserve the async throwing handler, captured multipart content, diarisation/language variants, model/host/auth assertions and validation tests. Reuse one fixture instance per test or explicit test subcase, with deterministic cleanup. If #1114 is concurrent, coordinate body capture representation; avoid contradictory transport edits.
2. SpeakCore `TTSTransportMockURLProtocol`/`TTSTransportStub` in TTSProviderTransportDoubles.swift: update consumers to hold a fixture instance rather than static set/reset. Keep TTSTransportCallCounter, XCTAssertTTSThrowsAsync, JSON response helpers and Gemini PCM response fixture. The file is not disposable merely because its protocol moves. If this fanout is unexpectedly large, migrate one ordinary core provider file instead and document remaining TTS conversion; do not churn every speech test to meet a subclass count.
3. SpeakiOS `BatchProviderRoutingTests`: both complete-response and record-then-throw userAuthenticationRequired cases fit. Preserve host and header isolation for padded direct-Google versus OpenRouter IDs, Cartesia service/status errors and empty transcript. Retain specialised OpenRouterCatalogHangingProtocol (headers plus incomplete JSON then hang and didStart/didStop), OpenRouterCatalogOrderingProtocol, AnalyticsRecordingURLProtocol (deferred controlled completion and cancellation), OpenRouterPendingSpeechProtocol and recording-loss protocols unless an individually inspected fixture is demonstrably ordinary. Do not replace partial response with no response, or defer with immediate completion. Keep `Sources/SpeakApp/CoreJourneyBatchFixture.swift` entirely outside scope.

## Meaningful verification

Add support-contract tests in an existing test target (or focused support test target) proving two simultaneous sessions with identical URL/method/body receive different fixtures; close/reset one while the other is pending and verify the other handler/recordings survive. Verify provider-created requests inherit session scope without headers/URL changes. Test concurrent requests in one session, handler throws, async handler, request stream capture available twice as immutable bytes, cancellation-before/during-handler and no late callbacks. Use expectations or controllable continuations rather than sleeps. Ordinary successful response must produce exactly one completion.

Before migration list discovered existing test names for affected suites; after migration compare names and assertion meaning. Existing coverage must remain, with new support tests counted separately rather than claiming total test count is unchanged. Adapt helper syntax as needed without weakening expected endpoints/fields/errors. Demonstrate fixture teardown prevents leaked handlers/session work, including test failure paths.

Run Apple Swift targeted core/app tests, Xcode iOS SpeakiOSTests and normal lint/build gates. Native Foundation URLProtocol/session association is essential; Linux source checks cannot establish it. Run the affected suites together/repeatedly only to resolve the concrete contamination risk, not an unbounded stress campaign. Inspect link graphs to prove support remains test-only and test imports work in Tuist. No production UI, provider API behaviour or latency improvement is claimed. Submit one scoped PR with migrated classes, intentionally retained specialised fixtures, exact test mapping and native evidence. Expand to more fixtures only after demonstrated value and compatibility, not to achieve a grep count.
