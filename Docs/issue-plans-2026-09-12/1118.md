# #1118 implementation plan: local history compatibility, then isolated persistence

Decision: NARROW; SOL medium, two separately reviewable increments. Introduce a shared local record with platform adapters, then move production iOS persistence off MainActor while preserving recovery and truthful durability. No CloudKit full-record upload, WAL replacement, legacy file rename or #1119 container choice. Read reviews/1118.json, AGENTS.md and current history tests before starting. Planning evidence is not a Beads update.

## Increment one: shared local record and compatibility adapters

Create `Sources/SpeakCore/HistoryRecord.swift` and a focused supporting-types file as needed. Make the immutable record Codable, Identifiable, Sendable and Equatable/Hashable where its value fields permit. Keep createdAt/updatedAt names, which Mac already uses. Include a schemaVersion for newly encoded shared records and explicit CodingKeys. Preserve all stored Mac fields plus iOS's primary model, wordCount, originPlatform and local errorMessage. Defaults for absent optional diagnostics must not fabricate a trigger, recording event or network exchange. Preserve nil versus empty transcript/processed text where callers distinguish them.

Move the portable value types actually declared in `Sources/SpeakApp/HistoryItem.swift`: HistoryEvent (+Kind), HistoryNetworkExchange, HistoryError (+Phase), HistoryTrigger (+nested gesture/output enums), HistoryCost, ModelUsagePhase, ModelUsage, PostProcessingPromptPayload, PhaseTimestamps and HistoryItemSource. Also move `HistoryDiagnosticContext`'s pure value definition from its separate Mac file. These are current top-level types, not the ticket's hypothetical nested NetworkExchange/Event/Cost names. Preserve field names, enum raw strings, initializer defaults and computed duration helpers. Keep any platform-specific capture/building extension in SpeakApp. Audit existing core `PersonalLexiconHistorySummary` and related correction values, `ChatCostBreakdown` and `SessionLatencyMetrics` for sound Sendable conformance; do not add unchecked Sendable to mutable reference state merely to compile the superset.

Keep `HistoryItem` and public `iOSHistoryItem` as real compatibility adapters with their existing initializers/properties, Codable representation and helper behaviours. A typealias alone does not preserve an exported module-qualified public type. Add lossless `historyRecord` conversions and failable/explicit platform construction as appropriate. A Mac record converted into an iOS display adapter must not discard rich fields if it will be converted back; either retain the source record privately for the roundtrip or keep rich conversion separate from the intentionally lossy sync projection. Do not claim a ten-field adapter can roundtrip a superset unless this is tested. Current iOS-origin records can remain simple legacy values.

Implement shared decoding of both legacy shapes using keys, not a guessed platform field: Mac rawTranscription/recordingDuration/modelUsages/modelsUsed; iOS transcription/model/duration/wordCount. Require genuine identity/date/text fields as their legacy decoder does; default absent iOS updatedAt to createdAt and originPlatform to ios. New shared versions should reject unsupported future schema versions visibly rather than silently drop unknown data and overwrite it. Preserve the existing ISO8601 strategies at store boundaries; Decoder's date strategy is caller-owned. Keep modelUsages versus deprecated modelsUsed fallback exact and do not rewrite identifiers. Preserve raw local URL and diagnostic values locally without interpreting them as portable resources.

`HistoryRecord.presentation` supplies `HistoryPresentationItem` using each adapter's existing choices: Mac modelUsages-or-modelsUsed, cost total and errors count; iOS one model, local error count and originPlatform. Delegate existing `presentationItem` properties through the shared projection after equality tests. Keep bestText/hasPolishedText, withPostProcessed clearing errors, and withError timestamp semantics unchanged. This is a concrete first consumer of the common record; no wholesale view/property rename is needed.

Both existing stores still encode their adapters in their original schemas. `Sources/SpeakApp/HistoryWALStore.swift`, its WAL format and all iOS primary/sidecar paths remain intact. `SyncableHistoryEntry`, `SyncRecord.record/entry`, `HistorySyncEngine`, MacHistorySyncAdapter and iOS toSyncable/fromSyncable keep the nine-field scalar projection. Explicitly test that iOS errorMessage, local file URLs and diagnostic/network payloads do not become sync fields. Versioning a local type does not authorise remote disclosure or a CloudKit schema rollout.

Generate deterministic synthetic/scrubbed fixtures with the real legacy encoders, not invented examples or private user exports. Place in `Tests/SpeakCoreTests/Fixtures` and register resources if necessary. Test Mac rich/minimal and iOS old-without-updatedAt/origin plus current-with-error shapes; UUIDs, dates, Decimal costs, latency, prompt/network/lexicon/trigger data, processed/raw text and model identity survive shared decode and same-platform roundtrip. Test malformed required fields, unknown version and nil-versus-empty. Retain HistoryItemModelTests, HistoryItemLatencyTests and HistoryPresentationTests.

## Increment two: actor isolation with ordered, truthful durability

Do not simply mark `IOSHistoryPersistence` an actor and wrap calls in Task. `iOSHistoryManager` currently loads before init returns; public synchronous `upsertReportingDurability` returns true only after durable storage, and `recordTranscription` returns a row only when saved. Watch imports, completion receipts and Handoff rely on this. Current `HistoryManagerPersistenceTests.testColdManagerLoadsExistingHistoryImmediately` codifies old compatibility. MainActor cannot synchronously await an actor without a problematic blocking bridge.

Add explicitly asynchronous production entry points (`loadIfNeededAndWait`, `upsertAndWait`, `recordTranscriptionAndWait`, removal/clear/flush equivalents) and migrate durability-sensitive production callers, including recording completion, Watch import and sync acknowledgement, to await them. Keep old public synchronous APIs/signatures as compatibility paths; do not return optimistic success. The practical compatibility design is one private serial persistence worker owning the existing state machine and disk operations, plus an `IOSHistoryPersistence` actor facade for asynchronous production use. Existing synchronous adapters invoke that same worker synchronously; they may still block their caller, which must be documented, but production migrated paths await work off MainActor. Do not create a second encoder/state/claim store or use semaphore waits on actor tasks. Queue work is pure persistence and never synchronously dispatches back to MainActor. If this bridge proves disproportionate, ship increment one and require a separately approved public async migration instead of silently breaking durability.

Move all current `StorageIO` reads/writes/removes, JSON coding, SHA256 per-item digest creation and recovery state into the worker; injected closures must be safe on its serial executor. Return immutable Sendable operation results containing rows, durability, isReady, errorMessage and recoveredIDs rather than asynchronously reading several mutable properties. Keep observable items/loading/errors/syncedIDs on MainActor.

Use one ordered operation stream per manager, with monotonically increasing mutation revisions or a single chained task, so load, remember/upsert, deletion, clear and save cannot overtake each other. A cold async load must merge every mutation admitted while it was suspended; it must never publish an older loaded array over newer visible entries. Do not independently launch one Task per row then assume actor mailbox ordering matches UI intent. The store owns authoritative pending mutations and applies them before snapshot; revision-tagged results prevent stale completions overwriting newer UI state. Preserve remote commit debounce and only clear its pending flag for the committed revision.

Keep the exact existing primary `transcription-history.json` and `.recovery` formats, ISO8601/sorted-key digest basis, legacy array sidecar decoding, missing-file error distinction and completeFileProtectionUntilFirstUserAuthentication writes. Never treat unreadable/corrupt primary or sidecar as empty. Preserve pending deletes, same-second edits via per-item baseDigests, changed-primary wins after successful commit/failed cleanup, retained pending state and retry messages. No `.migrated` rename, WAL import or new storage root. `persistRemoteChanges`/didAcknowledgeSyncedEntries must await durable commit before acknowledgements. Lifecycle background flush must retain an appropriate existing background assertion or await a supported lifecycle hook; fire-and-forget app termination work is not guaranteed durable.

Preserve synchronous compatibility tests and add asynchronous production tests instead of deleting immediate-load coverage. Existing sync compatibility initialization may still block on the worker, so move production singleton construction to an internal lazy-load mode only after its callers await readiness; keep the public/static access safely initialized, with no app-wide bootstrap change. Initial UI loading is explicit, and mutation-before-ready tests prove old rows survive.

## Required tests and acceptance

Retain `HistoryRecoveryTests`, `HistoryRecoveryReviewTests`, `HistoryManagerPersistenceTests`, `HistorySyncReconciliationTests`, Mac HistoryManager/HistoryPersistenceFailure/MacHistorySyncAdapter tests and core/sync suites. Add injected delayed-read tests for add/delete during cold load, overlapping upsert/clear/remote commit, newer UI revisions versus old completion, delayed polish of an existing row and concurrent retries. Final disk state must match admitted operation order. Fault tests cover unreadable primary/sidecar, partial write failure, same-second edits, pending tombstones, successful commit with failed sidecar removal and subsequent cleanup retry. Confirm Watch source material is not deleted and receipts/Handoff do not claim saved history before awaited durability succeeds.

Verify disk/hash operations execute outside MainActor on production async paths; checking only the `actor` keyword is insufficient. Run native Apple lint/build, history/core/sync suites and iOS build/SpeakiOSTests, plus API compatibility against base. Linux proves neither Apple file protection nor actor/UI responsiveness. Device upgrade gates on Mac and iOS: seeded old history visible, add/polish/delete survive restart, cold headless recording preserves prior entries, unavailable storage yields truthful recovery UI, sync banner unchanged. Record outstanding device checks explicitly. Submit each increment separately with on-disk/wire invariants and migrated durability callers. Common WAL and expanded sync remain deferred follow-ups, not incomplete acceptance hidden behind a refactor title.
