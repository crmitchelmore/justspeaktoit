## Verified format and architecture

Primary sources checked2026-09-12: OpenRouter's [dedicated TTS endpoint](https://openrouter.ai/docs/guides/overview/multimodal/tts) returns raw audio bytes and documents MP3/audio-mpeg. It also offers PCM but does not establish sample rate/channel/sample representation sufficiently for this implementation. Keep the existing explicit response_format="mp3"; do not confuse this endpoint with chat/SSE audio. Keep model-specific voices and omitted provider speed exactly as today. Use Apple [AudioFileStream parser](https://developer.apple.com/documentation/audiotoolbox/audiofilestreamopen(_:_:_:_:_:)), [Audio Converter Services](https://developer.apple.com/documentation/audiotoolbox/audio-converter-services) and [AVAudioPlayerNode](https://developer.apple.com/documentation/avfaudio/avaudioplayernode) for incremental parsing, decoding and scheduled PCM. Use shipping SDK APIs, not newly advertised beta replacements.

Pipeline: one bounded HTTP request writes its original MP3 to the existing private temporary file while feeding one serialized parser/decoder; awaited PCM delivery provides backpressure into the existing/native playback adapter. The same completed MP3 remains the result/export artifact. HTTP chunks are arbitrary byte fragments, not MP3 frames. Never play a growing MP3 through AVAudioPlayer/AVURLAsset or treat compressed bytes as PCM.

Existing `TTSProgressivePlayer` is reusable but not ready unchanged: its waitForHeadroom eventually schedules beyond its nominal10second limit, and buffer callbacks are not generation-fenced. Existing iOS OpenRouterIOSAudioPlayback's session lease and interruption policy must survive; the Soniox-only player should not become a new competing cross-provider framework in this task.

## Implementation contracts

1. `Sources/SpeakCore/OpenRouterAudioClient+Download.swift`: add an internal awaited speech-byte observer to the existing download loop, preserving the old perform signature via an overload. Validate status, MIME and Content-Length before notifying playback; retain redirect policy, byte counting,32MiB speech limit,90second request timeout,120second response deadline, nonempty check and0600 file permissions. Feed ordered bounded chunks (initial target at most1KiB, independent of filesystem flush size) so32KiB accumulation does not postpone first audio. No Task per chunk/unbounded AsyncStream. A cancelled/throwing consumer cancels the URLSession task and cleans the partial file. STT downloads and old synthesize behavior remain unchanged. Label memory bounds as app-owned buffers, not a claim about URLSession's internal allocation.
2. Add `Sources/SpeakCore/OpenRouterProgressiveSpeech.swift` and `IncrementalMP3Decoder.swift`. The operation owns parser/converter, current request identity, byte/packet/PCM counts and a once-only terminal state. Use AudioFileStreamOpen with MP3 hint, metadata callbacks and complete packet descriptions; copy callback-owned data before returning. Serialize native parser/converter calls on one controlled executor; C callbacks record output/errors synchronously, then the owning async operation awaits PCM consumption. Never suspend inside a C callback or hand its pointers across actors. Configure conversion only after a valid source ASBD; normalize supported mono/stereo speech to little-endian signed16-bit mono24kHz PCM for the existing Mac chunk contract.24kHz is the LOCAL conversion output, not an assumption about provider output. Reject unsupported/changing formats safely and test actual source-rate conversion/downmix. Keep compressed/metadata backlog bounded (initial256KiB), decoded pending output at most1second and emissions at most100ms. Bounds/constants are explicit and tested.
3. Preserve one parser across network chunks so ID3 headers, MPEG headers, VBR and frame reservoirs survive fragmentation. EOF flushes pending converter output and validates the supported fixture/parser contract; no success on zero frames, known incomplete packet or reported decode failure. Do not assume HTTP success or AVURLAsset duration proves an untruncated MP3. Record any native parser limitation detecting truncation as an explicit qualification limit and add supported-frame validation where required, rather than silently accepting known malformed fixtures. Dispose AudioFileStream/AudioConverter exactly once on cancellation/failure/finish, with no stale callbacks after disposal.
4. Add an additive `OpenRouterAudioClient.synthesizeProgressively(..., onPCM:)` returning a small OpenRouterProgressiveSpeechResult containing the existing OpenRouterSpeechResult and playback disposition (`pcmProduced` or `completedFileRequired`). Retain every existing public initializer, synthesize signature and OpenRouterSpeechResult initializer; no default-argument replacement of old symbols. Share request construction/credential validation with normal synthesis, and preserve nil/unknown cost. The core does not open an audio session or own UI. Decoder callbacks may only expose generated audio to the caller, never persist text/keys or log provider bodies.
5. Fallback is explicitly once-only. When progressive playback is disabled, local speed is not1, or a pre-playback capability/setup limitation is detected, use the existing completed-file path. If the request already started, finish THAT SAME bounded download and play its validated completed MP3; never synthesize again, switch model/voice or make another billable request. A local progressive unsupported-format/parser-setup limitation may select completedFileRequired only before the first PCM buffer is committed to playback. Malformed/truncated audio, HTTP/limit/deadline failures and user cancellation remain failures, not fallback signals. Once any PCM buffer has been accepted for playback, never automatically replay the completed file from the beginning. On subsequent failure stop cleanly and report interruption; explicit user retry remains a separate action. Use the conservative scheduling boundary, since software cannot know exactly when a human heard the first sample.

## Platform integration and ownership

Mac: extend `TextToSpeech/TTSProgressivePlayer.swift` with an awaited bounded enqueue/drain operation used by OpenRouter. Reserve headroom BEFORE scheduling; if stalled/paused beyond the bounded5second wait, throw/cancel rather than exceed the10second ceiling. Split oversized PCM chunks. Fence completion callbacks, drain waiters and cleanup by utterance generation so stopped A cannot decrement B's frames or stop B's engine. Cancellation resumes pending waits; EOF drain has a bounded playback-duration-based deadline and cannot hang indefinitely. Preserve existing providers' public/internal method signatures and add regression coverage for their wrapper behavior.

`TextToSpeech/OpenRouterTTSClient.swift` adds a narrow progressive adapter around the new shared method, mapping errors through existing ttsError and converting complete results into the existing TTSResult. `TextToSpeechManager.performSynthesis` uses a small OpenRouter-specific operation helper when the internal gate, autoplay and speed1 permit; this helper owns player start/drain and the completedFileRequired branch. It returns the result plus whether playback has completed so the existing common publication/usage/export path runs ONCE and never autoplays twice. Keep the existing ProgressiveTextToSpeechClient PCM contract unchanged for other providers; no second general TTS protocol hierarchy. Preserve synthesisID guards and OpenRouterSpeechOutput temporary-file ownership. If cancelled before publishing a returned result, remove its file; the manager owns it only after accepted publication. Non-autoplay/export and non-unit speed retain existing completed-file playback/rate semantics in this first increment.

iOS: add `Services/OpenRouterIOSProgressivePlayback.swift`, using the same decoded PCM contract with generation-fenced AVAudioPlayerNode, strict bounded scheduling and cancellation/drain. Extract only the existing private OpenRouterIOSAudioSessionLease into a shared iOS helper used by BOTH file/progressive adapters: preserve record-category refusal, playAndRecord/multiRoute borrowing, restore-if-unchanged and never deactivate an unknown prior active session. Preserve interruption/route-loss/media-services handling and do not reconfigure a recording owner's newer session. `OpenRouterIOSVoiceOutputClient.speak/stop` retains its public signatures, operationID guard and file deletion; one helper chooses progressive versus completed-file playback. Stop/replacement cancels download, decoding, scheduled buffers and waits before old callbacks can affect the next request. Router ownership remains with VoiceOutputRouter; no new recording coordinator. Model-detail previews keep existing file playback initially; scope the internal gate to normal speech output and test it explicitly.

Use one immutable internal option passed through construction; retain old constructors with default-off behavior. Do not add a user-facing preferences framework or enable all discovered models merely because the MP3 parser builds. Broader speeds/formats and metadata controls remain optional follow-ups after this slice is qualified.
