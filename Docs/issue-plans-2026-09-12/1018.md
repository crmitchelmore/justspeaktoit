# #1018 qualification plan: post-stop runtime on the shipping SDK

Decision: NARROW to a documented SDK probe and controlled native comparison. No production conformance, scheduler, recording ownership or clipboard rewrite is authorized by this review. The old polishing placeholder is already removed; #994 preserves immediate raw clipboard and no later overwrite, #996 safe recovery and #999 strict-local choices. #993 owns capture/finalisation bounds.

## Primary-source finding and remaining gate

Apple’s official DocC JSON read on 12 September 2026 publishes these declarations:

| API | Published availability / shape |
| --- | --- |
| LongRunningIntent | iOS 27; inherits ProgressReportingIntent. |
| AppIntent.allowedExecutionTargets | iOS 27; static IntentExecutionTargets property, including `.main`. |
| CancellableIntent | iOS 26.4; cancellation cleanup support. |
| ProgressReportingIntent | iOS 17. |
| LongRunningIntent.performBackgroundTask(options:operation:onCancel:) | Generic async throwing operation, Sendable cancellation-reason callback, constrained to Self: CancellableIntent. |

Sources: [LongRunningIntent](https://developer.apple.com/documentation/appintents/longrunningintent), [execution targets](https://developer.apple.com/documentation/appintents/intentexecutiontargets), and [background operation](https://developer.apple.com/documentation/appintents/longrunningintent/performbackgroundtask(options:operation:oncancel:)). JSON metadata is published documentation, not proof that the project’s selected shipping SDK contains those symbols or a physical OS executes them. Record exact supported Xcode/SDK/OS versions before using the declarations. Do not upgrade the release toolchain or deployment target to make the experiment compile.

Apple describes regular real progress reporting and cancellation of unprogressing work, with a system Live Activity for the task. A single slow opaque provider request may not provide meaningful incremental progress. Do not fake progress with a timer or infer that a wrapper grants unlimited execution. The `.main` property selects an allowed target; it is not proof of foreground state or microphone permission.

## Concrete deliverable now

Write Docs/post-stop-runtime-qualification.md with the declaration table, exact SDK probe commands/results, current baseline lifecycle and device matrix. Linux can prepare this dossier and synthetic slow-response test specification. On an authorized Apple runner, inspect SDK interfaces and compile the smallest isolated example using these symbols in a non-shipping qualification target. Runtime `#available` alone cannot make an unknown symbol compile on an older SDK. If absent from the selected shipping SDK, record the exact compiler/SDK gate and stop; do not add dead production API scaffolding.

The existing baseline is TranscriptionRecordingService.startPostProcessing plus BackgroundTaskAssertion and AutomaticPolishOperation; StopTranscriptionRecordingIntent is an AudioRecordingIntent/LiveActivityIntent and refuses separately owned foreground capture. Authenticated StopDictationIntent’s optional Wait For Polish has a whole-operation budget and raw fallback. Trace those actual paths before probing alternatives. Retain their current tests and no detached polish lifetime claim.

## Controlled comparison after SDK proof

Use a test/internal-only adapter and a deterministic local HTTP fixture serving a synthetic polish response after a controlled delay. Keep it out of shipping targets and avoid provider credits. Reuse the existing injected polish closure to model immediate success, slow success, no progress, timeout, cancellation and failure. Then run the actual candidate intent runtime on a physical supported iPhone; a closure sleep in XCTest establishes only unit ownership, not OS runtime extension.

Compare baseline and candidate with the same synthetic finalized raw text, History ID, network delay and device state. Wrap only the post-stop task actually awaited inside performBackgroundTask; wrapping a method that launches detached polish and returns does not extend that detached work. If representing the current lifetime requires substantial production restructuring, record the constraint and stop adoption rather than rewriting the service during qualification. Any candidate progress reflects completed stages/bytes the operation actually reports, with no guessed percentage.

Record process/target identity, app foreground/locked state, capture owner, raw-ready time, assertion expiration, task cancellation callback, History/polish completion and visible activities. Verify the candidate and existing audio activity coexist without duplicate misleading result surfaces. Cancellation must settle once, preserve raw History, retain the existing clipboard contents and never affect a replacement run. Check disconnect, unsupported OS fallback, permission refusal, repeated Stop and rapid restart; no new microphone acquisition occurs after stop.

Physical tests include background/locked phone, display state, controlled long network wait, user cancellation, system expiration where reproducible, suspension/termination/relaunch and authenticated versus authentication-free intent entry points. Do not intentionally exhaust resources or claim termination cleanup is guaranteed. The ordinary Stop remains word-count/receipt only; private String return still requires authentication. Record actual behavior, including cases the OS cannot reproduce deterministically.

## Adoption decision

The result is qualified benefit, unavailable evidence, or no worthwhile benefit. A useful result must show a real post-stop completion improvement over baseline without delaying raw text, breaking cancellation/ownership, duplicating activities or requiring dishonest progress. SDK availability alone is not a go. If no gain or an incompatible opaque operation is found, retain current code and record that result. Production adoption needs a separately bounded reviewed change with supported-OS fallback and all existing #934/#993/#994/#996 tests. No Send to Mac, capture-phase runtime wrapper, Stable promotion, release dispatch or paid access is authorized.
