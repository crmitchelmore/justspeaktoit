## Contract and settings decision

Use native `UIPasteboard.setItems(_:options:)` with one UTF-8 plain-text item, `.expirationDate` computed at each successful write attempt, and `.localOnly` equal to the inverse of explicit Universal Clipboard permission. Apple documents localOnly as excluding Handoff eligibility and expirationDate as the system removal date; neither establishes a remote-deletion guarantee. Sources checked2026-09-12: [setItems](https://developer.apple.com/documentation/uikit/uipasteboard/setitems(_:options:)), [localOnly](https://developer.apple.com/documentation/uikit/uipasteboard/optionskey/localonly), [expirationDate](https://developer.apple.com/documentation/uikit/uipasteboard/optionskey/expirationdate). Apple [Universal Clipboard setup](https://support.apple.com/en-us/102430) requires compatible nearby devices, same Apple Account, Handoff, Wi-Fi and Bluetooth; eligibility is not a successful-transfer receipt. Markdown versions of the API docs were retrieved directly when the web renderer rejected their content type.

Make the concrete product choice five-minute expiry and local-only for fresh installs AND upgrades without an explicit new choice. Offer a native finite picker:1,5,15minutes, plus a separate Universal Clipboard toggle, off by default. Do not infer opt-in from a previous clipboard destination or Handoff availability. Do not add Never in this bounded change. The setting affects future writes; changing it neither rewrites the current item nor retracts remote/pasted copies or History.

Add exactly named iOS defaults `transcriptClipboardLifetimeSeconds`, `transcriptClipboardAllowsUniversalClipboard`, `transcriptClipboardNoticeVersion` to AppSettings.DefaultsKey. Retain all17 old raw keys and values. Store finite integer seconds and a genuine Boolean; decode persisted types explicitly so strings, negative/unsupported values and Boolean-as-number do not silently become approved choices. Invalid/missing values resolve to300/false. Notice version1 denotes an explicit acknowledgement, never mere settings construction or a headless write. Persist choices independently from acknowledgement. These settings remain device-local iOS preferences; do not add them to SettingsSync, ConfigTransfer's string dictionary, shared keys, CloudKit, or macOS defaults under #1116.

## Minimal implementation

1. New `Sources/SpeakiOS/Services/TranscriptClipboard.swift`: a small immutable `TranscriptClipboardPolicy` and finite `TranscriptClipboardLifetime` enum, plus one `@MainActor TranscriptClipboard` adapter. Keep policy default resolution independently testable. The adapter takes an injected pasteboard seam (changeCount and setItems), clock, and policy supplier evaluated at WRITE time. Its `@discardableResult copy(_ text: String) -> Bool` rejects empty strings without touching pasteboard, invokes setItems exactly once with `UTType.utf8PlainText.identifier`, and reports whether changeCount advanced. No pre-write `.string` assignment, ownership tokens, sleeps, delayed cleanup or retry. Never trim/reformat nonempty text. Keep UIKit type-erasure/Any confined to this actor-bound adapter.
2. Use one concrete system instance wired to AppSettings.shared's current policy; defaults and clock are injectable for tests. AppSettings owns persistence; do not create a competing singleton settings framework or initialize credentials/model selection from the pure policy decoder. Preserve AppSettings initializer signatures. In `Settings/AppSettings.swift`, add published lifetime/eligibility values and a small acknowledgement method backed by the same injected defaults. Normalize initial invalid values predictably; preserve an explicit false and an explicit valid lifetime across restart.
3. In `Services/AutomaticPolishOperation.swift`, retain `PolishPasteboard.write`, `SystemPolishPasteboard`, `PolishClipboard` initializers and the existing automatic injection seam. Have SystemPolishPasteboard delegate to TranscriptClipboard; do not change its void contract merely to share an explicit-copy result. Retain `PolishClipboard.copyRaw`'s empty guard. `TranscriptionRecordingService.applyDestinationSideEffects` still makes precisely one raw write; `clipboardHolds` stays read-only. AutomaticPolishOperation still has no pasteboard capability. History Only, keyboard insertion and empty capture do not create new clipboard writes.
4. Route ALL explicit transcript writes through the adapter: `Activity/TranscriptionIntents.swift`'s `CopyLastTranscriptIntent.copyConfirmingChangeCount`, `CopyLastSentenceIntent.perform`, `CopyFullTranscriptIntent.perform`; `Views/ContentView.swift.copyToClipboard`; and HistoryView's `onCopyRaw`, `onCopyPolished`, leading swipe Copy. Preserve source selection, completionID/authentication checks, raw/polished fallback and copy wording. Completion Live Activity becomes copied only after observed success; no-write/failure must not be presented as success. The other intents keep their existing success responses and receive a safe failure response when the adapter returns false. ContentView's two-second copied-indicator task can remain: it changes UI only. No clipboard-clear task. Check current notification handlers and extensions for any additional transcript writer; current surveyed source contains no independent notification writer, so do not invent one.

Universal Clipboard is off. Enable it to allow copying between your Apple devices. Expiry does not delete History or copies already pasted elsewhere.” Render the actual selection, not hardcoded five after changes. State that expiry on another device is not guaranteed. Replace the obsolete “Send to Mac / Local network only” row in this view with accurate Universal Clipboard wording while touching its disclosure; this is not restoration of that removed feature. Update any clipboard-specific active-workflow disclosure in `Services/PrivacyWorkflowSummary+AppSettings.swift` only if needed to avoid conflicting claims; do not treat Universal Clipboard as an AI provider recipient.

For unacknowledged policy version, show a persistent, nonmodal notice in ContentView's existing scroll content, before optional onboarding cards. Suggested heading “Clipboard privacy updated”; show effective settings with native buttons “Clipboard Settings” (opens the existing Privacy destination) and “Got it”. The settings destination must allow an immediate explicit toggle and lifetime choice. Only an intentional acknowledgement records version1; rendering, entering background, recording or a copy does not. Put the same explanation/current settings in `Views/Settings/HardwareTriggerSettingsView.swift` next to clipboard destination guidance so headless users can discover the cause of changed Mac pasting. Fresh installs also see the defaults before dismissal; do not rely on hasLaunchedBefore, whose bootstrap semantics are unrelated.

A headless first launch immediately uses safe defaults and keeps the notice pending until the next foreground visit. Include the changed default and exact Settings path in release/upgrade notes; do not claim an unseen notice was delivered. Preserve parameterless toggle/control intents' no-value/no-dialog contract: appending a migration dialog can become a Shortcuts clipboard payload and undo #934. Do not force a foreground launch, grant notification permission, add a notification channel or block capture to show this notice. Record this migration tradeoff explicitly in the PR and device evidence; a user who never opens the upgraded app may only see release messaging. If product requires acknowledgement before the very first headless policy change, that requires a separate product decision; do not silently preserve unrestricted legacy clipboard writes.
