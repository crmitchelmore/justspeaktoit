# #996 executable plan: safe typed start-failure presentation

Decision: NARROW to the accepted review and comment5622114142. Fix misleading permission guidance and raw error disclosure at existing start-error surfaces. Do not implement the ticket's universal CaptureCommandRouter, analytics schema, journal/Live Activity payload expansion, or an app-wide dependency bootstrap. #1025/#1070 already supply CaptureCommandRunner; #944/#1084 supply terminal publication. Preserve #943 ownership, #934 raw clipboard and #935 intent result contracts. #1117 injection may improve tests later but is not a prerequisite.

## Existing boundaries and proposed value

`Sources/SpeakiOS/Activity/TranscriptionIntents.swift` catches typed parameter/ownership refusals but StartTranscriptionIntent.perform's final catch tells every other error to check microphone/speech permissions. `iOSTranscriptionError` already distinguishes real permission denial, recognizer availability, audio session, recognition, Live Activity and startup timeout. Its audio/recognition descriptions interpolate arbitrary underlying localizedDescription. `CaptureCommandRunner.surfaceStartFailure` passes arbitrary error text into the existing pure policy, then publishes PresentedFailure. ContentView presents both direct foreground catches and published background errors.

Keep the decision WHETHER to show a failure in `Sources/SpeakCore/CaptureStartFailurePolicy.swift`: cancellation, supersession and foreign microphone ownership remain silent; publication-token deduplication remains unchanged. Add one iOS presentation mapping describing WHAT safe message/recovery to show. Do not replace lifecycle decisions with a taxonomy switch.

## Implementation sequence

1. Add `Sources/SpeakiOS/Services/CaptureStartFailurePresentation.swift`. Define an immutable, Equatable, Sendable presentation value with message, stable local code and optional small recovery enum (`appPermissions`, `credentials`, `prepareAppleModel`; add only a real existing destination). It may conform to LocalizedError to flow through the existing `(Error)->Void` publication seam. A pure factory maps existing typed errors; UIKit/SwiftUI navigation stays outside. Unknown errors produce “Recording couldn’t start. Try again, or open the app to check your setup.” with code `start_unknown`, no permission attribution and no arbitrary text. No provider names, model-supplied strings, URLs, credentials or response bodies in spoken/public copy.
2. Use this concrete mapping table. Permission.microphone/speechRecognition each get distinct safe copy/code and appPermissions action. `AppSettings.CredentialLoadingError.unavailable` maps temporarily inaccessible secure storage to unlock/retry guidance; it does not mean missing credentials. `StreamingClientError.missingAPIKey(provider:)` maps actual missing credentials to the existing API Keys UI without printing the associated provider identifier. Preserve this distinction when a route instead refuses as CaptureParameterFailure.modelUnavailable. `iOSTranscriptionError.recognizerUnavailable` describes selected-language recognition unavailable, not missing assets without evidence. `audioSessionFailed` says microphone/audio could not start and suggests retry after another audio activity; do not assert another app owns it. `liveActivityUnavailable` gives existing open-app/Live Activities guidance, with only a supported Settings action. `startTimedOut` may use closed-set StartupStage copy, never stringify arbitrary metadata. Recognition unknowns remain safe failures. Preserve CaptureParameterFailure and CaptureLinkFailure semantics and existing callback codes; presentation does not remap `.modelUnavailable` into permissions.
3. Missing Apple model currently originates as the app-owned `NSError(domain:"AppleSpeechPreparation",code:1)` in `iOSLiveTranscriber.modelPreparationError`. Recognize that exact domain/code as a compatibility bridge or replace this private producer with a typed case while retaining existing public errors. Never detect errors by substring matching. Map unavailable assets to the actual Prepare Apple model settings action. Underlying error wrappers may unwrap only explicitly supported typed causes; bound any unwrapping and never expose their descriptions. Sanitize iOSTranscriptionError.audioSessionFailed/recognitionFailed public descriptions as well, since intent errors can escape through paths beyond the one catch. Keep raw errors available only to existing private diagnostics; review log interpolation privacy rather than adding logging.
4. In StartTranscriptionIntent.perform, preserve parameter validation/ownership branches first; CancellationError must not become a terminal permission dialog. Return a neutral cancelled outcome for that dialog-bearing intent without success wording. Map only real remaining failures to safe IntentDialog. Toggle/control intents retain existing no-value/no-dialog success signatures; where they currently throw startup errors, throw the safe mapped LocalizedError after preserving cancellation and ownership behavior. Do not introduce a result string that Shortcuts can copy over a transcript. `startRecordingContinuingInForegroundIfNeeded` still retries ONLY liveActivityUnavailable, awaits the continuation and passes the same StartupEntry/run parameters. Do not retry provider/network/permission failures through foreground continuation.
5. Treat declined continuation carefully: Apple's API forwards continuation results/errors, so an error caught around requestToContinueInForeground can be a retry's real failure. Do not label every thrown error “user declined”. Preserve CancellationError unchanged; identify an OS decline only with a documented typed signal supported by the shipping SDK or bounded device evidence. Otherwise use a neutral continuation-unavailable message without claiming user intent. Keep this uncertainty explicit in tests/device notes; do not use guessed NSError codes. The current API's deprecation does not authorise migrating all intents to dynamic supportedModes in this issue.
6. In CaptureCommandRunner.surfaceStartFailure, create the safe presentation, feed its message to the existing disposition function, and publish that typed presentation only for `.surface`. Keep `(Error)->Void`, StartOutcome callback failure codes, capture identity and destination handling unchanged. Do not throw away recovery metadata by wrapping back into message-only PresentedFailure. The old public PresentedFailure initializer/type and policy overload remain for compatibility; accept it safely at the adapter boundary where existing callers/tests use it. In ContentView, retain a typed pending recovery action alongside errorMessage for start failures. Update direct start catches (manual and auto-start) and the published session-error presentation path to use the mapping when the error is a mapped start failure. Never classify every runtime interruption/finalisation/import failure as startup; those existing surfaces retain their own ownership and text policy.
7. Extend ContentView's existing alert with a recovery button only when a supported action exists; reset it when unrelated errors replace the alert so a stale credentials button cannot accompany another failure. Permissions use UIApplication.openSettingsURLString, not private prefs schemes. Credentials/Apple preparation open the already existing native Settings destination, without bypassing authentication or starting downloads automatically. Preserve token-based cold-launch/repeated-failure handling. Do not require dismissal/retry confirmation to continue an unrelated active capture.

Apple primary references checked2026-09-12: [openSettingsURLString](https://developer.apple.com/documentation/uikit/uiapplication/opensettingsurlstring) documents the app's Settings destination, not a direct link to every permission pane. [requestToContinueInForeground](https://developer.apple.com/documentation/appintents/foregroundcontinuableintent/requesttocontinueinforeground(_:continuation:)) documents forwarding the continuation result and now advertises deprecation; this plan preserves the existing deployment-compatible call rather than expanding scope.

## Tests and gates

Test cancellation/decline handling without asserting undocumented OS codes. Reuse `CaptureStartFailureVisibilityTests` to prove the runner publishes safe typed recovery metadata, suppresses cancelled/superseded/foreign-owned failures, and preserves callback refusal semantics. Existing tests that expected arbitrary LocalizedError text should intentionally change to safe fallback expectations at the iOS adapter, while pure core policy compatibility tests still pass.

Add focused adapter tests for intent mapping, no recording-started result after cancellation, and foreground continuation retry failure versus cancellation. Reuse existing injected closures/service seams; do not invoke real permission prompts in unit tests or wait for #1117. Run CaptureCommandRunner/destination tests, foreground ownership/startup race tests and CaptureStartFailurePolicyTests. UI tests verify permissions/credentials/model preparation buttons route correctly, generic failure lacks a misleading repair link, repeated token failures each alert once, and replacing an alert clears stale recovery.

Exact-head Apple app/iOS library/extension build, relevant native tests and lint are required. On physical iPhone, test denied mic, Live Activities disabled, accepted and declined foreground continuation, unavailable prepared assets and missing credentials using synthetic setup; verify actual Settings navigation and no duplicate capture. Device behavior/OS error identification remains pending if unavailable on Linux. No analytics calls, secret-bearing error artifacts, runtime router replacement or automatic provider retry is authorised.
