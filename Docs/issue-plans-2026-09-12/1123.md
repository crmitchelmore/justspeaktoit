# #1123 implementation plan: a compiled Watch shared module

Decision: IMPLEMENT; SOL medium. Replace shared file-path compilation with a dependency-free module/product while preserving Watch capture, release identity and existing SpeakCore source compatibility. Read reviews/1123.json, AGENTS.md and current manifests. Coordinate #1120/#1122 and release catalogue changes. No CloudKit migration, provision changes, feature-flag enablement or release dispatch.

## Prove the package boundary first

The current root SpeakCore target already has no package-target dependencies, yet Project.swift documents a Watch package graph compatibility problem. A new dependency-free target in the same root manifest is therefore a hypothesis, not proof that resolution succeeds. First make the smallest manifest/source-boundary patch and use Apple Tuist/Xcode to generate with `TUIST_WATCH_APP=1`, build the actual `JustSpeakWatchApp` and `JustSpeakWatchWidgetExtension` targets for watchOS Simulator and inspect dependency resolution. Adding watchOS support to root must not require adding watchOS to unrelated third-party manifests or bundling iOS/macOS clients into Watch.

Preferred shape: root `SpeakWatchCore` library product and dependency-free target at `Sources/SpeakWatchCore`, root platform `.watchOS(.v10)`, and SpeakCore target depends on SpeakWatchCore. If the same-manifest graph remains incompatible, use an isolated dependency-free local package (for example `Packages/SpeakWatchCore`) with its own product/target/platforms and make root SpeakCore and Tuist Watch targets depend on it. Keep one canonical source directory inside that package; do not restore source-path copies, symlink across target roots or duplicate files. Record the native error driving the fallback. Choose only after the native graph probe; no broad manifest dependency rearrangement.

## Move the seven canonical files

Move these from `Sources/SpeakCore` to the chosen Watch module: WatchCaptureProtocol.swift, WatchComplicationState.swift, WatchRecordingLifecycle.swift, WatchRecordingToggleSerialiser.swift, WatchSharedContainer.swift, ReleaseTrain.swift and ReleaseTrainCatalogue.swift. Preserve Foundation-only behaviour and all current encoded keys/raw enum values. No audio/provider/runtime library dependencies belong in this module.

Audit visibility member-by-member. Most wire/lifecycle types are already public. `WatchRecordingToggleSerialiser` is currently internal; the Watch coordinator needs its class, initializer and `run` public, while acquire/release/state remain private. `WatchRecordingRequest.claim` and nested Claim currently cross no module boundary but are used by `JustSpeakWatch/WatchRecordingCoordinator.swift`; expose only the claim/member operations actually required by that coordinator, preserving atomic claim/finish semantics. WatchSharedContainer.names/claim can remain internal because their consumer moves with them. WatchCaptureCoding and generated ReleaseTrainCatalogue remain internal implementation details; moving files does not justify making everything public.

Keep `ReleaseTrain.current` exactly equivalent: ALPHA compiler condition takes precedence, otherwise Bundle.main metadata and bundle identifier determine identity; invalid metadata/precondition protections remain. The moved module must receive any required compile condition where it previously relied on direct Watch target compilation. A compiler define on the app target does not automatically propagate to a package target. Use explicit Stable/Alpha package tests plus generated Watch app metadata tests to prove the fallback is equivalent. Never replace Bundle.main with Bundle.module, which would change identity/storage selection. Preserve all app-group/namespace/catalogue bytes and stable fallback behaviour.

Keep `Sources/SpeakCore/Resources/ReleaseTrains.json` canonical. Update `scripts/generate-release-train-config.py` TARGET to the new generated Swift file and its check path; SOURCE stays canonical JSON. Run generation twice and --check, expecting deterministic/no second diff. Project.swift's JSON read is legitimate and stays. Do not make the generated catalogue public or copy JSON into a competing authority.

Add a focused SpeakCore re-export file using the existing project's supported export convention (ticket proposes `@_exported import SpeakWatchCore`) so `import SpeakCore` callers still resolve public moved names. Re-export preserves source lookup but is not by itself proof of module-qualified binary/API compatibility. Run `scripts/check-api-compatibility.sh <base>` early; inspect emitted public symbol changes. Preserve existing public type/method signatures and supply narrow forwarding compatibility declarations if the repository's exported API gate needs them. Do not modify an allowlist or label a breaking relocation 'additive' merely because source builds. If preserving an actual binary promise needs a materially larger wrapper design, report that specific constraint before expanding; new public Watch-only methods are additive.
