## Stage 2: ElevenLabs shared realtime transport

Files: `Sources/SpeakCore/ElevenLabsLiveClient.swift`; optional small `ElevenLabsRealtime.swift` for internal wire builders/decoding if file length requires it; new `Tests/SpeakCoreTests/ElevenLabsLiveClientTests.swift`; update ElevenLabs fixtures in `StreamingClientContractTests.swift`. The API validator at the bottom of the client file is unrelated and must remain functionally unchanged.

Verified protocol facts: the endpoint is `/v1/speech-to-text/realtime`, authenticates with `xi-api-key`, and uses `input_audio_chunk` JSON containing base64 audio. Configure `audio_format=pcm_<sampleRate>` and retain VAD segmentation. `session_started` gates readiness; `partial_transcript` replaces the current segment and `committed_transcript` commits it. `commit:true` requests a commit. Timestamp transcript events are additional delayed messages, not new utterances. [ElevenLabs API reference, checked 12 September 2026](https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime).

Implementation requirements:

- Preserve ALL existing public symbols: initializer, start, both audio send forms, stop, isConnected, finalShape, finishAndWait, finishFlushesBufferedAudio, error enum and validator. Keep `.standaloneSegments`. Change `finishFlushesBufferedAudio` to true because this implementation now sends an active commit.
- A single internal request builder must set model ID, PCM format, `commit_strategy=vad`, and existing optional `language.localeLanguageCode`. Keep timestamps/language-detection extensions off; do not add ElevenLabs keyterms or billable options as extra scope.
- Use JSON text for audio with original PCM bytes base64 encoded and sample rate. The finish frame is an empty `input_audio_chunk` with `commit:true` (same shape used by the mac implementation). Reject audio submissions after finishing begins.
- Gate sends on the actual handshake, not URLSession's `.running`. Retain the existing bounded `StreamingAudioPreroll`. On handshake, drain it immediately, even if no new microphone chunk arrives. Preserve exact PCM order when a send races with handshake/drain. Avoid copying/rescanning all prior audio on every chunk.
- Provide a narrow, internal fakeable socket seam for the TWO clients whose transport changes here. For example an internal protocol exposing resume, callback send/receive, cancel and state; use URLSessionWebSocketTask through a thin adapter and an internal injected factory initializer. Keep public session-based initializers intact. First inspect existing seam patterns and reuse one if suitable. This is justified to test frame ordering and real finish state transitions without paid calls; do not migrate other clients or create a generic provider framework. Pure message-builder tests alone cannot establish this behaviour.
- Serialize outbound frame admission and finishing so a raced audio frame cannot land after commit. Use one per-session serial queue or a lock-protected ordered send pump. A bounded audio admission budget can reuse `StreamingAudioSendBudget`; do not grow an unbounded queue while a socket is stalled. No blocking main-actor waits.
- Install finish waiters BEFORE any commit can complete. Use one generation/session identity carried by socket receives, send completions, readiness waits and deadline closures. An old session cannot append into, resolve, close, or emit errors for a new session. Starting again first resolves the previous session's waiters with that session's snapshot and cancels its socket; then resets state. Repeated concurrent finish calls join the same finish operation and each resume once; a single overwritten continuation leaks callers.
- Stop during handshake must retain the captured audio while waiting for readiness within a bound, then flush and commit. Suggested budget: existing readiness budget 2 seconds and up to 1.5 seconds after commit, with one overall ceiling of 4 seconds including sends. Expose short internal timing settings to fixtures. On failure/timeout/disconnect return the accumulated committed transcript, or nil; never promote interim-only text to a confirmed final. Explicit `stop()` cancels immediately and resolves all waiters. No delayed global `stop()` may target a restarted socket.
- Keep receiving committed segments during finish and fold every segment into `TranscriptAccumulator`. Do not infer duplicates from text equality: two `Yes.` commits are two utterances. Since timestamps are disabled, ignore `committed_transcript_with_timestamps` as enrichment, avoiding the duplicate-final bug in the mac parser. Blank committed text must not hang completion handling.
- IMPORTANT inference: VAD can have a pre-existing commit in flight, and the reference shows no commit correlation ID. Therefore the first committed frame received after sending manual commit is not proof that the tail was flushed. Minimal safe implementation should continue receiving until its bounded post-commit drain deadline (or explicit terminal close/error), rather than early-close on the first final. Report this deliberate 1.5-second stop tradeoff; future optimisation needs provider-correlated evidence. Do not add a heuristic quiet timer and call it an acknowledgement guarantee.
- During finish, committed finals are consumed by the full-transcript return, not also delivered as final callbacks. Ordinary recording callbacks remain provider-shaped. Ignore late events after completion. Preserve existing public `isConnected` transport meaning unless documented otherwise; internal readiness is separate.
- Decode real `message_type` events. Map auth and terminal provider errors to existing public errors or internal NSError as appropriate, and resolve finish on terminal failure. Unknown frames are harmless. Log event category/state only, never raw frames/audio/transcript/key-bearing request URLs.

Transport fixtures: prove endpoint/header/query and exact round-trip PCM bytes; no binary audio; pre-handshake buffer then automatic ordered replay; stop-before-handshake replay then commit; audio send completion held while finish waits; a VAD final followed by a later tail both retained; empty commit response; multiple real identical commits; timestamp enrichment does not duplicate; explicit stop/error/timeout resolve every waiter; stop/start while an old receive, send completion and timeout are pending cannot affect the new session; empty session returns nil. Update the contract fixture from the obsolete speech_event_type/transcript shape to actual message_type/text. Existing contract tests currently pass against the wrong protocol and must not remain as the transport evidence.

## Stage 3: Soniox bounded server finalisation

Files: `Sources/SpeakCore/SonioxLiveClient.swift`; new `Tests/SpeakCoreTests/SonioxLiveClientTests.swift`; Soniox cases in `StreamingClientContractTests.swift`; shared internal transport seam from stage 2 if introduced.

Verified protocol facts: a finalize control commits preceding audio and returns final tokens followed by `<fin>`. Empty binary or text input ends the stream; the server may send multiple responses before `finished:true` and closure. `<end>` is not the same evidence as that session-finished response. [Manual finalisation](https://soniox.com/docs/stt/rt/manual-finalization), [WebSocket ending/response contract](https://soniox.com/docs/api-reference/stt/websocket-api), checked 12 September 2026.

- Add `FinalizingStreamingTranscriptionClient` conformance and `finishAndWait()`, with flush capability true; retain initializer/public send/stop and cumulative final shape. Keep initial authentication/configuration shape and endpoint unchanged in this issue.
- Use the same lifecycle isolation principles as stage 2. The current shared DispatchGroup across sessions is insufficient isolation; outstanding completions must belong to their own session. Do not let an old group notification close a new socket or resolve its waiter.
- Order initial config before PCM; stop receiving new audio when finish starts; drain bounded preroll and pending PCM; enqueue existing `{"type":"finalize"}` then empty binary EOS. Keep receive loop alive after send completions. Wait for `finished:true` (or terminal disconnect/error/deadline), not just DispatchGroup completion. Record `<fin>` but do not close on it when awaiting EOS; later final response tokens still belong to the result. Suggested one overall ceiling: 3 seconds including setup/send drain; internal shorter budget for tests.
- Parse every response's tokens into cumulative final text before considering its finished flag. Strip control markers from display. Interims remain full final-prefix plus current nonfinal token batch. Never append token text twice by calling flush from both marker and finished branches; consolidate end-of-response final delivery. During a finish wait, return final text instead of a duplicate final callback. Outside finish, suppress duplicate marker/finished notifications when accumulated text has not changed, using state/version rather than discarding repeated spoken tokens.
- `stop()` is the immediate abort/cleanup path for the finalizing protocol. Its existing best-effort finalize/send-wait logic is replaced by explicit `finishAndWait` graceful behaviour. Inspect direct callers for an expectation of graceful stop; platform shared consumers already discover conformance dynamically. Resolve all in-flight waiters and cancel only their socket. No unbounded background work. Already-gone socket returns the full accumulated final text; interim-only sessions return nil.
- Soniox tests: ordered config/PCM/finalize/EOS; finish remains pending after all sends complete; several token responses before finished; `<fin>` before later final tokens; marker and finished in one frame; duplicate marker frames do not double final callbacks; token repetition remains legitimate speech; blank/error/silent sessions; pre-ready capture; send failure; disconnect; bounded timeout; repeated finish callers and stop/start generation races.
- Add contract tests using `{"tokens":[{"text":"Hello","is_final":true}]}`, another final token batch, and `{"tokens":[],"finished":true}`. Assert full accumulated result, graceful conformance and flush=true. Existing `StreamingAudioPrerollTests` must continue to pass; do not remove coverage to accommodate the rewrite.
