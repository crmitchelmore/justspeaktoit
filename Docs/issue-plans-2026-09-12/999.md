# #999 executable plan: capability-checked strict offline live routing

Decision: NARROW per reviews/999.json and comment5622113485. Implement an early known-offline decision and strict local processing for that route. Defer automatic cloud retranscription, pending flags, background tasks, upload queues, batch-model substitution and History replacement. Existing CaptureRecoveryCoordinator remains the sole manual saved-audio recovery owner. Base implementation on #996 error presentation and current stacked #994 clipboard policy (PR #1136 head 091fb7a, including #1115); coordinate #1113 routing/credentials and preserve selected-model/location persistence. Keep the shared TranscriptClipboard writer and all 20 local defaults, including the three clipboard privacy keys. No cloud request or extra cost is triggered by reconnect.

## Boundaries and routing policy

`TranscriptionRecordingService.resolveLiveModelHonouringRequest` currently prevents credential fallback from replacing an explicitly named run model; ordinary streaming may visibly fall back. Foreground RecordingCoordinator in `Views/ContentView.swift` also resolves credentials before constructing the same IOSTranscriptionSession. Apply the same new pure policy at both existing owners; do not unify their lifecycles. Batch, explicitly bound keyboard profiles, Compare Models and saved-file recovery keep their current model contracts.

Use a three-way network snapshot: unknown, available, unavailable. Only a delivered NWPathMonitor update with status.unsatisfied means known unavailable. Before first update, after monitor cancellation/restart and for requiresConnection/unknown future cases, treat status as unknown. Never await a first update in the start path, issue reachability probes or equate satisfied with a working provider. A snapshot is advisory; once a run chooses strict local it remains strict even if connectivity changes.

| Input | Decision |
|---|---|
| Ordinary remote live selection, known offline, local capability ready | Use strict Apple legacy local model for this run, visibly describe offline fallback; preserve global preferred model |
| Ordinary remote live selection, known offline, local capability unavailable/unknown | Refuse promptly with a typed recoverable offline/local-unavailable failure; do not open the remote socket or silently choose another paid model |
| Explicit per-run remote model or keyboard-bound profile, known offline | Refuse as unavailable with existing explicit-model semantics; do not substitute |
| Unknown/requiresConnection or available path | Retain current credential/provider decision and failure handling; no promise of connectivity |
| Already selected local model | Retain its identity; no substitution into cloud. Its strict/local support checks still apply |
| Batch or manual saved-audio retry | Outside automatic fallback scope; preserve existing explicit flow |

Missing credentials and inaccessible Keychain remain distinct: preserve current explicit-request refusal and ordinary fallback policy, while preventing an offline credential fallback from losing the strict-local requirement. Known offline can skip irrelevant remote connection work, but cannot turn a malformed/unsupported explicit model into a valid default. Evaluate against the user's validated requested model and effective locale before a credential fallback erases the reason for substitution.

## Exact implementation

1. Add `Sources/SpeakiOS/Services/OfflineCaptureRouting.swift` with Sendable snapshot/capability values and a pure route decision. Inputs include mode, validated requested model, explicit/profile binding, connectivity and locale-specific local capability. Output is unchanged, strict-local effective model with safe notice, or typed refusal. Reuse LiveTranscriptionRouting/ModelCatalog and existing model IDs rather than a new provider registry. The bounded fallback target is `AppleLocalModels.legacySpeechModelID`; do not introduce ranking/downloads across every installed engine. An already selected SpeechAnalyzer model keeps its existing installed-only engine checks.
2. Add a small `CaptureNetworkPathMonitor` adapter, owned once by the existing iOS service/app dependency lifetime, using Network.NWPathMonitor. Start asynchronously when that owner is initialized, with one serial callback queue and MainActor-isolated state update. Inject snapshot providers into the existing service and foreground coordinator initializers using retained old overloads; #1117 can later group these dependencies. Never create one monitor per recording or use unsynchronized mutable globals. A cancelled/restarted monitor must discard its old generation's updates and reset to unknown; release resources with its owner.
3. Add a tiny injectable Apple local capability probe on MainActor using the exact recognition locale. For the legacy fallback, require recognizer existence, appropriate availability and supportsOnDeviceRecognition; unknown/unavailable support is not permission to try server recognition. These are supported capability checks, not proof that every installed asset will work. If an additional authoritative installed-assets check is unavailable for the legacy API, do not invent one or claim one was made. A later strict startup failure remains recoverable. Do not probe by starting recognition or downloading models. Resolve locale through the same TranscriptionLanguageCatalog/Locale path that actual session construction uses; never fall back silently to English.
4. Carry the strict processing requirement as one immutable per-session option into `Sources/SpeakiOS/Services/IOSTranscriptionSession.swift`'s construction/makeBackend and the existing Apple transcriber. Retain old initializers/start symbols. Add a clearly separate internal `requiresStrictOnDeviceRecognition` flag or enum; `preferOnDevice` cannot express a hard privacy constraint. Use strict for the newly selected offline route and for app-selected models whose catalogue/UI promises local processing. Preserve the legacy public preferOnDevice behavior for compatibility callers without that hard requirement. Do not change default cloud selection/preferences.
5. In `Services/iOSLiveTranscriber.swift`, enforce strictness at BOTH `setupRecognition()` and the rolling legacy restart path that creates a new SFSpeechAudioBufferRecognitionRequest around line839. Guard supportsOnDeviceRecognition before task creation, set requiresOnDeviceRecognition=true on every strict request, and fail safely if capability disappears. Never allow the current else branch that logs server-based recognition for a strict run. Audit analyzer-to-legacy fallback too: `startCapture` can fall back after analyzer preparation failure; it may do so only when the legacy replacement satisfies strictness AND the existing explicit-model/analyzerFallbackAllowed contract permits substitution. Otherwise propagate a safe typed refusal. Current `startSpeechAnalyzer` already uses `.installedOnly` and bounded AppleSpeechDependencyWait/AppleSpeechAssets; retain those, do not add network asset installation during capture.
6. In `TranscriptionRecordingService.startRecording`, decide after validated per-run selection/locale resolution and before creating a remote session, update currentModel only for the session, and reuse providerFallbackNotice for “Offline — using on-device speech recognition.” Feed effective model through existing session/History/Live Activity presentation and preserve requested global settings. In RecordingCoordinator.startCapture, apply the same decision before IOSTranscriptionSession construction and publish its existing warning/presentation field with the same safe message. Check cancellation/run identity after any awaited capability work, and unwind using existing owner logic. A reconnect notification never changes the running session, calls recovery or creates another History row.
7. Use #996's mapper for the typed offline/local-unavailable error if available; otherwise add a small iOSTranscriptionError case with safe copy and existing Prepare Apple model/settings guidance, ready for that mapper. Do not misreport permission denial, claim missing assets solely from unsupported locale, or tell users a preflight refusal recorded audio. Preflight may happen before any audio exists: refuse truthfully. Once capture has begun, retain existing safety recording/warning/claim semantics on startup/runtime failure and offer the existing manual recovery route for actual saved files. This issue does not add a record-only offline recorder. Preserve History identity, raw-once clipboard, empty0writes and manual user edits.

Apple sources checked2026-09-12: [NWPath statuses](https://developer.apple.com/documentation/network/nwpath/status-swift.enum) distinguish unsatisfied from requiresConnection; [supportsOnDeviceRecognition](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition) describes local capability; [requiresOnDeviceRecognition](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/requiresondevicerecognition) requires both capability and the request flag. These document the privacy controls, not measured device latency or successful local recognition.
