## Small implementable documentation change

In Docs/automation.md, under “Behaviour worth knowing”, correct the request-ID description to `mcp-<process-scope>-<call-id>`, bounded by AutomationLimits.maxIdentifierLength. Explain that reuse of the same call ID within a server process uses the app’s cached reply, while a new server process receives a new scope; do not promise cross-process exactly-once execution or unlimited cache retention. MCPRequestHandler.requestID(for:) is the authority: its static processScope is an eight-character UUID prefix and the final identifier is truncated. Do not change that implementation merely to simplify prose.

Keep the current standalone installation guidance and app-owned credential boundary. Historical bundled-binary commands are evidence for their versions, not the preferred current setup. No schema, protocol-version, microphone or Send to Mac changes are needed. Check documentation links and source agreement; a new implementation-mirroring test is unnecessary. Existing MCPServerBehaviourTests remain the regression suite if code changes later become justified.

## Native named-client run

This planning task performs no installation, registration, setting changes or client calls. The qualification executor needs an authorised Mac, an existing usable Claude Code account/client, a running supported app and installed standalone speak CLI. Missing client/account/installation is a specific pending gate, not a server failure. Use existing access; do not purchase credits or silently install software.

1. Record date, macOS/architecture, app version/build, resolved standalone executable path and `speak --version`, plus `claude --version`. Inspect only the target server’s existing configuration and preserve it for restoration without exporting unrelated configuration/secrets. Prefer an isolated local working directory and local registration scope so repository/user-wide settings are unchanged.
2. Arrange one explicitly non-sensitive existing History entry suitable for disclosure to Claude Code. The MCP socket is local, but a real agent client can place returned text in its model conversation; do not describe the entire journey as on-device. Do not select private History merely because the final report will redact it. If no suitable entry or consent exists, pause the call gate rather than manufacturing History or using paid transcription.
3. Record the current Automation toggle. With authorised temporary local Automation opt-in, verify `speak status --json` reaches the running app. Keep the established same-user socket design; no network listener or relaxed permissions. This opt-in enables the surface’s microphone/history capabilities even though this bounded run invokes only get_history.
4. Verify installed CLI help against the current vendor syntax, then register the documented `speak mcp` command in local scope. The current primary reference supports `claude mcp add --transport stdio --scope local justspeaktoit -- <absolute-speak-path> mcp`; quote the executable path as a single shell argument. Do not overwrite an existing registration: reuse it if identical or choose an explicitly temporary name. See [Claude Code MCP documentation](https://code.claude.com/docs/en/mcp), checked 12 September 2026.
5. Open the real Claude Code client and its MCP status/tool view; verify connection and discovery of exactly transcribe_file, get_history, start_dictation and stop_dictation with documented arguments. Configuration-written output alone is insufficient. Ask that client to call get_history with limit 1, inspect the actual tool result, and record success plus content/structuredContent shape and item count. Do not substitute hand-written JSON-RPC or a mock client. No file transcription or microphone calls are required for this issue.
6. Restore the original registration and Automation state, including on failure. For an originally disabled toggle, confirm the socket disappears and a fresh actual call cannot obtain History. If originally enabled, test disabled access briefly and restore the original state. Remove only the temporary registration; retain unrelated configuration and account state. Do not promise previously returned client content is remotely erased by disabling Automation.
