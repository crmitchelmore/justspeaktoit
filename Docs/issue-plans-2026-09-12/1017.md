# #1017 implementation plan: optional private completion notifications

Decision: NARROW, SOL medium. Add a disabled-by-default generic saved-result notification for eligible background phone completions and Watch imports. No transcript preview option, clipboard action, AppEntity donation, automation template or iOS 27 trigger claim. Preserve #994 clipboard privacy, #996 errors and #999 routing. Notifications report saved readiness; they neither execute background transcription nor establish delivery to another app.

## Settings, payload and permission

Add local `transcriptReadyNotificationsEnabled` to extracted AppSettings and a native toggle in the existing result/destination settings area. Preserve all existing raw keys and any concurrent #1009 additions; add an explicit mapping test for this new key rather than restoring a stale total. No sync or ConfigTransfer export. Explain that alerts contain no transcript and appear only when there is no other active result surface.

Request UNUserNotificationCenter authorization only from an intentional enable action, following [Apple notification permission guidance](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications). Request only the permissions used, initially alert without sound/badge. Denial leaves the toggle off with concise Settings guidance; do not re-prompt on launch, capture, or import. Re-check current authorization when scheduling because system Settings may change. Opt-out increments a generation, cancels outstanding scheduling and removes this feature’s pending requests only; do not remove unrelated remote/history notifications. Do not enumerate or clear previously delivered user content unnecessarily.

Create `TranscriptReadyNotificationCoordinator` in Sources/SpeakiOS/Services with injected authorization/enqueue/removal, clock, settings and deduplication storage. Use title “Transcript ready”, generic body “Open History to view your saved transcription”, a constant category/thread identifier and userInfo containing only schema version and exact History UUID. No raw/processed text, snippet, model, locale, source tag, receipt body or filename. Default tap and an “Open History” action open the same identified record; use foreground action activation and the existing device unlock boundary, never authentication-free Copy.

## Eligibility and exact persistence boundary

A pure policy input contains enabled/authorization, app foreground state, actual matching result-surface state, keyboard delivery outcome, successful nonempty durable History ID and capture failure. Initial rules: suppress if disabled, unauthorized, foreground, empty, cancelled/failed, saveToHistory false, durability false, keyboard confirmed insertion, or a matching active Live Activity already owns the result. A late-pickup keyboard offer is not confirmed insertion. Treat an existing active matching activity as a reason to suppress without claiming it is visible to the user; no arbitrary delayed fallback/re-notify when it later dismisses. Activity absence is not evidence of execution permission.

In TranscriptionRecordingService.stopRecording, reuse its non-nil historyItem after the current recordTranscription call: in the inspected #999 source, recordTranscription returns only after upsertReportingDurability succeeds. Record that actual contract, not the older comment suggesting every History insertion is merely in-memory. If #1118 async persistence lands, await its equivalent confirmed durability. Evaluate after keyboard outcome and result publication are known, once per completed run, before optional polish is awaited; freeze the History ID and status before any scheduling await. No notification for a failure merely because a partial transcript was salvaged. Scheduling failure never changes the capture receipt, clipboard result, History, retry journal or assertion cleanup.

In WatchCaptureImportPipeline.importOne, use job.captureID, which is the History row ID. Schedule only after persistHistory(item) returns true and existing successful import commit/acknowledgment is secured. Keep offerToKeyboard and optional reprocess semantics. A notification must never cause retry of paid transcription, delay source acknowledgment indefinitely or delete retained audio after persistence failure. Existing import retries must not create repeated alerts.

Readiness means the transcription is saved now; polishing may update that same History row later with no second notification. Do not wait for polish, reuse capture completion UUID as a History UUID, or load mutable latest text to construct navigation. Synced/backfilled History insertions are not additional notification sources in this issue; #1007 has separate arrival ownership.

## Deduplication and navigation

Serialize eligibility/claim/enqueue in the coordinator. Use stable request identifier `transcript-ready.<history UUID>` and a small local, protected atomic ledger of attempted eligible History IDs. Claim durably before enqueue; if the claim cannot persist, skip the alert. Repeated callbacks, import retries, app restart and concurrent captures cannot claim the same ID again. A crash between claim and enqueue may lose a notice; this is acceptable best-effort at-most-once scheduling and must not be called guaranteed delivery. Do not implement a retry queue or erase claims on transient enqueue failure. Keep transcript text out of the ledger; define cleanup with explicit local History deletion/clear without expanding CloudKit wire fields.

Add a narrow pendingHistoryID route to Sources/SpeakiOS/Services/DeepLinkRouter.swift or the existing navigation owner, and consume it in ContentView’s History presentation plus HistoryView’s identified selection. The current router has no identified History route, so this small addition is part of implementation, not an assumed existing API. Preserve release-specific schemes and capture URL precedence. UUID-validate notification input; load History before resolving, open only that row, and show a neutral “Transcript is no longer available” state for a deleted ID. Never substitute the latest record. A cold tap must not trigger start/stop or write clipboard.

Wire UNUserNotificationCenterDelegate through existing SpeakiOSAppDelegate without replacing remote history push handling. Retain completion-handler exactly-once behavior and current app lifecycle registration. Foreground willPresent suppresses this category; unrelated notification policies remain with their current owners. No new extension, entitlement or background mode is needed for a local notification request.

## Tests and native gates

Add pure eligibility tests and coordinator fake-center/storage tests: opt-out zero authorization requests, denied permission, revoke during await, concurrent IDs, duplicate ID/restart, failed claim/enqueue, empty/failed/persistence-error capture, active matching activity, unrelated activity, foreground, confirmed keyboard delivery and Watch retry. Assert serialized payload has no transcript fields and raw-versus-polished completion yields one request. Test cold/deleted/wrong UUID navigation without latest fallback. Reuse existing service completion, Watch import durability and #994/#996 tests; notification failure must leave their outcomes unchanged.

Run Apple UserNotifications/App Intents build and affected iOS tests, strict lint and normal required CI. Physical acceptance covers toggle/permission denial, locked hidden-content display, background completion with/without Live Activity, foreground suppression, cold notification tap, deleted History, concurrent captures and Watch retry. Killing the app may prevent capture/import completion entirely; report that as lifecycle evidence, not a notification defect that promises new background execution. Notification enqueue success is not delivery proof.

Future automation requires official target-OS contracts and one actual automation showing its available variables. Record that gate separately; this stable generic title does not establish a Shortcuts trigger, sub-second timing or unattended fan-out. No paid credit, remote post, release dispatch or Stable promotion is authorized.
