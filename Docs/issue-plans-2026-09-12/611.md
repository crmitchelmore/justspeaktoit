# #611 qualification plan: insertion correctness and measured latency

Decision: NARROW to measurement and target qualification. No implementation PR unless a measured gap justifies a separately scoped fix. Credit #644 and #780: LiveTextInserter already streams/reconciles stable regions and records firstInsertionAt; LatencyInsights already aggregates per-provider firstPartial/firstInsert/stopToFinal sample counts and p50/p95, plus capture-start overview. The stale comment about insertion percentiles is superseded. #664 owns qualification of the current two-app allowlist; #611 retains expansion beyond those two and any later independently reviewed AX-region improvement.

## Reproducible baseline

Use an existing authorised build on physical Mac with real microphone and existing provider credentials. Record source/build, hardware/RAM, OS, microphone/route, target app/version/field, provider/model, language, network conditions and experimental streaming setting. Use synthetic fixed passages, including corrections, punctuation and Unicode. No paid-credit activation, provider preconnection, audio prewarming or release dispatch is authorised.

First inspect existing HistoryItem latency data and LatencyInsights to confirm the actual checkpoint definitions in the tested build. Log per-session captureStartMs, firstPartialMs, firstInsertMs and stopToFinalMs, session/model identity, insertion mode and missing-value reason. firstInsertionAt is an insertion-path checkpoint, not independently observed display paint. Label it accordingly. Record externally observed first visible text and confirmed correct final field content as separate observations; do not equate accepted AX writes with verified reconciliation. Hotkey-to-audio, capture-to-first-partial and capture-to-insertion must retain their own time origins. The historical “cold start under100ms on a warm app” mixes conditions; report process-cold and already-running conditions separately.

For a bounded first pass select one local engine and one existing authorised cloud model, two currently supported streaming targets and one fallback target. Per condition collect20 warm runs, plus10 process-cold starts per engine; record startup/preparation/cache state and exclude setup runs only when explicitly marked before collection. Alternate engine/target order to reduce ordering effects. This is a baseline, not a statistically stable tail-latency claim. Use existing per-session data and dashboard; a read-only local extraction from an authorised History copy is sufficient if fields are serialized. Do not add a production exporter merely for convenience. If required checkpoints truly cannot be extracted, report the specific absent field first; propose a narrow measurement helper only then.

Calculate per-condition sample counts and p50/p95 with the existing LatencyPercentiles convention. Keep failures, cancellations and missing measurements separately visible rather than converting missing to zero or discarding failed runs. Do not mix streaming first insertion with one-shot final paste, or warm and cold samples, into one headline. Compare measured warm capture-start against100ms as a target; a miss is evidence for investigation, not permission for speculative warm-engine work.

## Per-app correctness matrix and ownership

Current StreamingInsertionAllowlist includes only TextEdit and Notes. Slack, VS Code and browser contenteditable fields are deliberately excluded because full-field AX readback may be unreliable. Keep that allowlist unchanged during qualification. Under #664 finish current TextEdit/Notes qualification and the setting-off/nonallowlisted baselines, preserving the detailed owner results. Under #611 assess the remaining requested target classes, recording excluded targets as paste-at-end coverage rather than claiming streaming support. A numeric “five apps” goal does not authorise adding unsafe entries.

For each supported field test empty insertion, replacing a selection, corrected partials, punctuation/emoji/combining characters, caret motion, focus/app changes, user edits during dictation, denied/stale AX access and readback failure. Compare final text and surrounding content against the intended result: no duplication, overwritten unrelated text or garbling. Check deferred readiness and safe fallback behavior. Nonallowlisted fields must retain one-shot delivery. Screen recording plus final field readback supports visible correctness; an AX success return alone does not. Record current allowlisted target/field failures under #664; route wider-app evidence and any expansion proposal through #611 before a separate fix.

Retain `HistoryItemLatencyTests`, existing insertion/allowlist tests and percentile behavior. Native Swift changes, if later approved, require exact-head Apple build/tests/lint. This qualification itself needs no new Swift tests. Publish benchmark wording only after actual samples and target results exist, with counts, conditions, insertion semantics and limitations; no competitor or universal speed claim follows from this plan. Device access unavailable means baseline/target gates pending, not issue complete.
