## Current contract and exact visibility

`Sources/SpeakApp/PostHogAnalytics.swift` is compiled out under APP_STORE. Its minimal sink has a1,000-event/seven-day durable queue, generation-fenced serialized flush, cancellation, bounded response/deadline and transient retry. `ProductAnalyticsController` already owns consent, random install identity and ordered purge/close. `WireUp.makeAnalyticsController` only permits direct builds with configuration; preserve absent-config/development no-op and Mac App Store compile-out.

The inspector must use actual `makeRequest` serialization, not `ProductAnalyticsController.preview`'s synthetic zero-ID example. Current HTTP body contains api_key, event and properties; the sink adds properties distinct_id, $lib, $lib_version, release_train and timestamp to typed event/context fields. Anonymous counters currently use distinct_id="anonymous-counter". Preserve these semantics. Display/export the exact event+properties object and clearly say “Ingestion credential omitted”; do not export api_key, authorization material, provider secrets, raw responses or user-level records from the server. JSON formatting may change, field/value identity may not. “HTTP acknowledged” reflects the sink's observed2xx response, not independently proven backend processing or exactly-once delivery.

## Bounded implementation

1. Factor the existing sink serializer into one internal credential-free event-envelope builder used by BOTH makeRequest and inspector records. Add the credential only inside request construction. Store immutable Sendable encoded JSON/Data and closed-set local delivery status; no general dictionary API that bypasses the typed catalogue. Keep the added event fields at their current location. Reading the inspector must never call capture, reopen, create an install ID, refresh remote config or otherwise produce traffic.
2. In PostHogProductAnalyticsSink add an actor-isolated snapshot API with configured endpoint, effective open/disabled state, current queue depth and at most100 recent event records. Use existing QueuedEvent.id for local row identity and update the same row across queued/in-flight/HTTP-acknowledged/retry-pending states, rather than counting each retry as a new captured event. Maintain a bounded in-memory history of this launch; seed it with at most100 still-valid persisted queued entries at construction. Label this scope explicitly: sent-event history is not retained across relaunch, queued events are. This avoids a second durable analytics archive or longer identity retention. Purge/reset/withdrawal clears the ring, and generation checks prevent a late response repopulating it. TTL/cap eviction removes or accurately marks represented entries. No response body is retained. Failed persistence must not be labelled durably queued.
3. Add `Sources/SpeakApp/AnalyticsPrivacyControls.swift`: a narrow MainActor observable adapter retaining the existing controller plus concrete sink for inspection and native operations. In `WireUp.swift`, have the private factory return/retain this service bundle without changing public API contracts or capture call sites. Store concrete PostHog references only behind !APP_STORE guards. Add core read-only installationID access that returns nil when absent; do not expose the state store or invoke installationID() from a view. Combine consent and sink snapshots with an operation revision so reset/withdrawal cannot leave old-identity rows on screen after completion. Do not read queue/state files independently from UI.
4. Add `ProductAnalyticsController.resetInstallationIdentity()` using existing consentRevision and suspension machinery: invalidate pending captures, synchronously establish closed admission before awaiting purge/close, purge queue/history and delete identity; preserve current consent choice. If still opted in and not disabled after cleanup, allow a new ID to be created lazily by the next actual approved event. Do not toggle settings off/on, capture analytics_opt_in again, clear unrelated app settings, or emit a reset event. Capture queued before reset must not send under the new ID; delayed reopen/response must not revive old work. Any cleanup failure remains fail-closed with truthful feedback and a retryable operation, without claiming server erasure. Preserve all existing public initializer/method symbols.
5. Operational local override: add `AnalyticsLocalPolicy` with a build/plist force-disable value and device-local `posthog.forceDisabled` defaults override; either true wins. Defaults are scoped to the current Alpha/Stable app identity and never synced/transferred. Optional POSTHOG_DISABLED environment input may support controlled local launches, but does not replace a persisted operator override. Use a small thread-safe value source for the existing @Sendable forceDisabled closure. Do not capture MainActor-isolated mutable UI state unsafely. Wire the SAME gate into controller and sink admission/flush/retry checks so a switch during reopen cannot flush queued data before the controller's later recheck.
6. Add an explicit controller `refreshCollectionPolicy()`/equivalent operation that revisions pending work and immediately uses existing suspension to cancel active requests/backoff, purge queue/history and delete identity when disabled. The running-app control invokes it immediately after setting the gate; do not wait for the next capture. Preserve underlying opt-in preference while showing effective sharing disabled. Clearing a forced build/plist flag is impossible from UI; clearing the local override only permits sharing if consent is still opted in. Operator `defaults write <actual bundle-id> posthog.forceDisabled -bool true` instructions require restarting the app for deterministic cross-process observation; do not promise defaults notifications reliably update a live process. Inspector may provide a native “Disable collection on this Mac”/explicit resume control using the same method, with force-source explanation. No remote poll or key rotation call.
7. `Views/Settings/SettingsView+About.swift`: retain permanent Share anonymous analytics consent and policy link; add a native Analytics Inspector sheet/window available in direct release builds. New `Views/Settings/AnalyticsInspectorView.swift` displays consent versus effective enabled state, endpoint, queue depth, current ID or “Not created”, bounded event list and selectable JSON. Provide Reset identity and Export controls with ProgressView, disabled repeated action while running, clear success/failure/cancel feedback and an explicit explanation that reset affects local future events, not server records. Use NSSavePanel/fileExporter with JSON and write only the approved snapshot after user chooses destination; no automatic upload/share. Export cancellation is neutral, failed write is visible, export itself creates no analytics event. Clear any operation snapshot/cached text when withdrawal/reset completes; already exported files remain user-owned and cannot be recalled.
