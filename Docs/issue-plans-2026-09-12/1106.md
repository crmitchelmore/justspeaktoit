## Provider facts checked 12 September 2026

The current official Auto reference documents binary PCM chunks (100 ms is its example), a JSON text close command that flushes buffered audio, and a `connected` event that clients need not await before sending. It does not establish a mandatory 50 ms minimum; that padding is an existing app convention to preserve, not an AssemblyAI rule to attribute to Cartesia. [Cartesia Auto reference](https://docs.cartesia.ai/api-reference/stt/turns/websocket).

The turn guide states that stopping audio is not equivalent to sending silence, and clients should send `{"type":"close"}` after audio and keep reading until the server closes. A first `turn.end` is not evidence that all remaining audio has drained. Updates are cumulative within a turn; eager end can resume. [Cartesia turn guide](https://docs.cartesia.ai/use-the-api/stt/turns).

The official example independently sends close after its final PCM and reads remaining events to completion. [Cartesia Auto example](https://docs.cartesia.ai/examples/stt-auto-finalize-websocket). Mono PCM16 at the declared rate matches the audio guide. [Cartesia audio input](https://docs.cartesia.ai/build-with-cartesia/stt/audio-input).

Qualification limit: the current reference is newer than the repository's pinned `2026-03-01`; the archived version page could not be fetched during planning. Keep the existing endpoint, Bearer scheme and version in this fold, and verify close compatibility on that pinned version during provider acceptance. Do not silently upgrade to the batch/TTS version (`2026-08-14`) or switch auth scheme because current docs display a different security heading.

### 1. Options, compatibility and test seam

Modify `Sources/SpeakCore/CartesiaLiveClient.swift` and the Cartesia branch of `LiveTranscriptionClientFactory.makeClient(for:apiKey:language:options:azureEndpoint:)`.

- Preserve the EXACT public `init(apiKey:model:sampleRate:session:)` with its current defaults and nonoptional `URLSession`. Forward it to a new overload with a required finish-options argument using the existing `LiveClientOptions` or the #1105 landed timing signature. Do not merely add a defaulted argument and remove an exported symbol. Keep all factory forwarding overloads.
- Factory passes the snapshotted grace/budget from `AppSettings.liveClientOptions`; SpeakCore never reads settings/defaults. Reuse #1105 timing sanitisation and valid user range. Legacy/default callers must get a safe bounded drain too.
- Add `FinalizingStreamingTranscriptionClient` conformance and `finishFlushesBufferedAudio = true`: finish really sends residual PCM and closes the provider input, so iOS must always use its graceful path, even with no visible unanswered interim. No iOS source migration is needed; its existing finalisation policy consumes this flag.
- Use the narrow fake socket/session seam landed for #1104/#1105 if accessible. If it is intentionally provider-local, add an equivalent small internal adapter only for Cartesia rather than broadening unrelated clients. Production and fixtures must share the same outbound ordering, parser and finish state machine. Fake receives, send completions, close and short timing/deadline injection are required; URL/message-builder-only tests cannot prove stop correctness.

### 2. PCM framing and session-scoped ordered sends

Move the deleted audio processor's framing responsibility into `CartesiaLiveClient`, with an internal `CartesiaPCMFramer` helper if useful. Reuse #1105's framer only if it is already parameterised and internal; do not force a shared public abstraction solely to eliminate a small helper.

- Compute preferred/minimum lengths from the configured sample rate: PCM16 mono, 100/50 ms. At 16 kHz these are 3200/1600 bytes. Accept arbitrary converter chunk sizes, emit preferred frames in order, and retain a residual. At finish pad only a nonempty residual below the minimum; a 50–99 ms residual is sent as-is. Empty audio must not create a silence frame. Keep PCM sample alignment and preserve original bytes before padding.
- Preserve bounded startup storage at two seconds of PCM (64,000 bytes at the route's rate), including its suffix eviction policy. Document that speech beyond this stalled-start cap is not guaranteed, rather than claiming unlimited first-word retention. Drain the retained bytes through the framer in order, not as one oversized binary message. Flush on usable transport/start, without waiting for the next capture chunk or for a Cartesia `connected` message.
- Audio admission, backlog drain, residual flush and close admission share one ordered send path and one per-session identity. `DispatchGroup` alone does not order racing sends. Pending work must remain bounded on a stalled socket; reuse the upstream send-budget helper when applicable and surface bounded failure if admission cannot continue.
- Every send/receive completion, timeout, error and delayed cancel checks the captured session/task. `receiveMessages` must recurse on its captured socket, not whichever socket became current. Clear pending PCM, transcript, callbacks and prior waiters safely at restart. Reject sends after graceful finishing begins and after abort; old callbacks cannot refill buffers or mutate a replacement session. Do not invoke callbacks/resume continuations while holding state locks.

### 3. Graceful finish and complete result

Implement `finishAndWait()` as the sole graceful path; `stop()` remains prompt abort/cancel and resolves any active finish callers. Repeated/concurrent finish calls join one operation and each complete exactly once. Capture the run before awaiting anything.

1. Atomically enter finishing, reject new capture audio, and arm result/terminal waiters. The shared controller has already stopped capture and serially drained its converter tail into this client.
2. Flush residual PCM, preserving order with all already admitted frames. Await their completion with the dedicated path's 1.5-second bound. During an unfinished handshake, let the existing transport send queue progress within that bound rather than immediately discarding short captured speech; do not invent a required server Begin event or reconnect during stop.
3. After admitted audio completes, send exactly one text frame `{"type":"close"}` on the same queue. Bound close-send completion too. A stalled/failed audio send must not be presented as successful tail delivery; report it, preserve available transcript and terminate the captured session within the bound.
4. Keep reading all turn events until normal server closure, terminal error, or the finish deadline. Do not finish on the first `turn.end`. Include the user grace as additional receive time on top of the provider budget while the socket remains open; normal server closure may return immediately because no more events can arrive. Do not add a cosmetic sleep after server closure.
5. Return the whole session transcript and leave a finalised result snapshot readable for the controller. On deadline retain confirmed turns plus last nonempty interim, as the dedicated controller did. Then cancel only this session, release timers/buffers and resolve all waiters once. Silence returns nil.

Choose a bounded initial post-close budget of 1.5 seconds as an implementation choice, not a Cartesia guarantee. Put its route default in `Sources/SpeakCore/LiveModelCapabilities.swift` (Cartesia currently has zero), and derive legacy defaults from the canonical catalogue, not a second model list. Reuse timing options for a selected-route override and user grace. Keep one total send stage of at most 1.5 seconds, then post-close budget plus valid configured grace; ensure maximum supported values remain below `TranscriptionManager`'s existing 10-second stop safety timeout. Explicitly account for grace at its UI maximum in tests; do not silently trim legitimate grace or alter global stop deadlines to mask an unbounded client. A provider smoke check must qualify whether 1.5 seconds is sufficient.

Errors during normal server-initiated close after the JSON close are terminal completion, not a fresh user-visible failure. Real auth/provider/network errors remain surfaced through the existing `StreamingClientError`/provider-error path. Handle provider error events before generic transcript decoding. Retain close-code/private-reason diagnostics if the seam allows them; never log credentials, full request URLs or user transcripts.

### 4. Transcript, segments and boundary parity

Keep production `transcriptEvent(from:)` coverage for existing `results` payloads and top-level `transcript`. Decode `turn.update` and `turn.eager_end` as replacement interim, `turn.end` as a standalone final. Nontranscript lifecycle/unknown events must not accidentally create partials; `turn.resume` does not erase the still-valid text. Do not finalise eager ends. Keep genuine identical final turns twice; `request_id` is a session identifier, not a unique turn/event deduplication key.

Use `TranscriptAccumulator(shape: .standaloneSegments)` plus current interim and finalised `[TranscriptionSegment]` state. A final clears its interim, appends one zero-time segment, and recording callbacks keep the existing provider shape. Finals consumed during finish update internal state and the return only; do not also append through final callbacks. Keep all late accepted finals until the server close/deadline. The result snapshot excludes a trailing unconfirmed interim.

Conform to #1105's `StreamingTranscriptSnapshotProviding`; return confirmed turn text, outstanding interim and finalised segments, leaving unsupported metadata nil. The controller snapshots it from its retained finishing client before clearing `self.client`, so explicit text projection never appends interim twice. Add a focused Cartesia assertion using this single upstream capability rather than another result protocol.

The dedicated controller never emits utterance boundaries. #1105's explicit-boundary capability also suppresses generic final/full-transcript boundary fallback. Use that existing conformance on Cartesia with its callback registration available but with no emitted boundaries in this parity fold; document this deliberate suppression beside the conformance. This preserves current automatic-polish triggering rather than introducing one on each end or full-history adoption. Enabling true standalone Cartesia `turn.end` boundary callbacks is an optional follow-up, not an excuse to add a provider branch in shared controller code. `MainManager` currently uses boundary callbacks as polish triggers; that is real product behaviour even though it ignores the callback text.

Preserve existing app whitespace joining for this migration. Current Cartesia documentation recommends verbatim turn concatenation; existing `TranscriptAccumulator` and dedicated controller insert spaces. Correcting that across live display/result consumers needs separately scoped fixtures/design, and is not permission to change the generic accumulator globally during this fold. Keep this known discrepancy in the PR, particularly for punctuation/turn-boundary provider testing.
