## 2. Result snapshot and cumulative transcript parity

Conform to the revised #1105 `StreamingTranscriptSnapshotProviding` using its single `StreamingTranscriptSnapshot`. Supply confirmedText from the existing cumulative final-token accumulator and pendingInterim from only the latest outstanding nonfinal token batch. Shared callback text already contains final-prefix-plus-interim; do not store that full callback as pendingInterim or append it twice. Keep #1104 `finishAndWait` confirmed-only semantics; the Mac snapshot preserves dedicated timeout fallback without promoting interim into a confirmed return or final segment. Confidence/duration/cost/rawPayload remain nil/defaults.

Preserve zero-time segment information without cumulative duplication: maintain a segment checkpoint cursor over the already accepted final-token sequence. At a real flush/finalisation checkpoint, create a segment from tokens accepted since the prior checkpoint, not from the complete cumulative string. Repeated markers with no new final tokens add nothing; repeated spoken tokens at distinct positions remain. On final result, checkpoint any remaining accepted final tokens once. Token position/version, not text equality or string-prefix guessing, determines new content. Keep provider-authored spacing inside token text and existing app joining at segment boundaries. This produces one segment in the normal single-final case and coherent disjoint segments for multiple checkpoints; document correction of the dedicated cumulative-segment bug.

`SharedClientLiveController` already consumes snapshot text/segments before releasing the finishing client. Use its default duration/model and no new metadata protocol. A snapshot read must be side-effect-free: finalisation checkpointing happens in the transport state machine before exposing the snapshot, not each time a consumer reads it.

Use #1105's explicit utterance-boundary conformance with no events, matching the dedicated Soniox path and #1106/#1108 suppression pattern. Do not translate cumulative finals or `<fin>` into new whole-history polish boundaries. Settings/language handling and preferred-input cleanup stay provider-neutral.
