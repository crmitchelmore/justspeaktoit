## Conditional native experiment proposal

Execution requires an available authorised Apple Silicon Mac, explicit asset/download permission or supplied existing assets, suitable free storage, and agreed corpus/resource budget. Those resources are not supplied by this plan. If supplied later, create an isolated experimental Swift package outside shipping manifests, using only MLXAudioSTT and its required dependencies at pinned revisions. Keep it outside root Package.swift/Project.swift and #1121 runtime decisions. Reuse corpus validation, WER/CER and resource-accounting conventions from the existing benchmark package (#1120 moves it under Benchmarks/LocalTranscription), but do not pretend its current WhisperKit/CTranscribe runners already exercise FluidAudio/Voxtral realtime. A small experiment adapter can produce the same schema plus explicitly versioned streaming timestamps; no benchmark framework rewrite.

Load verified local assets using the runtime's local-directory API after inspecting that it does not silently re-download. Network-disabled inference is a mandatory row; cached Hugging Face resolution is not proof of offline operation. Feed identical consented16kHz PCM to each engine at real-time cadence, not a full-file batch call labelled live. Use a bounded serial worker away from the real-time audio callback, sequence-number input/chunk accounting and a generation fence for callbacks. Measure cancellation latency of synchronous step/finish and model release; if stopping cannot bound compute/retire ownership, record no-go or a separate isolation requirement, not a fake cancel success.

Initial corpus:20 short English dictation clips with punctuation/names/numbers,5 longer2–5minute clips and a short silence/noise set, all with consent/licence and reference transcripts. Alternate models/order; five cold process/model-load runs and at least20 warm clip runs per model. Add a small explicitly supported non-English sample set to examine possible incremental language value; report Parakeet EOU unsupported-language cases as not applicable, not enormous WER or a fabricated comparison. Optionally compare an already installed appropriate multilingual local baseline without downloading another model by default.

Record input duration, cold load, first admitted audio, first partial, final input→final transcript, WER/CER, first/last-word errors, revisions, real-time factor, peak/resident and GPU memory, sustained growth, thermals/energy observations and disk footprint. Measure a ten-minute sustained run plus cancellation during load/step/finalisation, unload/reload and immediate next session. No dropped/duplicated opening/final samples or stale text may be hidden in averages. Separate numeric reproducibility from physical microphone qualification; a later real-mic row verifies tap/capture integration, while replayed PCM provides fair model comparison.

## Go/no-go and scope gates

Before running, record the Mac model/RAM/OS/Xcode and acceptable interactive resource budget for that host; do not choose an arbitrary universal1.5GB threshold retrospectively. A conditional engineering-go requires verified licences/local asset loading, bounded ownership/cancellation and a demonstrated dictation benefit over the existing baseline (accuracy, language coverage or latency) worth download/memory/maintenance cost. A model that runs but is consistently slower/larger without a useful gain is a valid no-go. Missing evidence is inconclusive, not an iOS no-go or macOS pass.

Production integration needs a separate approved plan only after measurements: existing LiveTranscriptionController/delegate and LocalModelPipelineLease ownership, honest readiness/download state, shared catalogue/platform filtering and exact public API compatibility. No app picker, native dependency or runtime-removal decision follows from a research-go. iOS remains separately unqualified until real-device memory/thermal, foreground/background, interruption and system-termination evidence exists; deployment target alone proves nothing. No purchase, inference, download, release or server action is authorised in this planning task. Parent owns publication of the dossier and subsequent asset/native execution decisions.
