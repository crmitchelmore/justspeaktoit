# #1113 implementation plan: shared model ownership with staged platform routing

Decision: NARROW. Assign SOL medium. Centralise model ownership and test catalogue coverage without claiming all transports or capture owners are already interchangeable. Read reviews/1113.json, AGENTS.md and plans #1104–1112; prerequisite approval is not proof of landed parity. This is planning evidence, not a Beads update.

## Separate ownership from capability

`LiveTranscriptionRouting`, `LiveTranscriptionRoute` and `LiveTranscriptionProviderID` already live in `Sources/SpeakCore/StreamingTranscriptionClient.swift`; extend that source of truth rather than add another live registry. The factory remains `LiveTranscriptionClientFactory.swift`. #1104's options and #1105's result snapshot/boundary contracts remain the configuration/result extension points. #1111 explicitly permits retaining iOS OpenAI's public capture adapter until overflow, interruption and recording-loss behaviour is demonstrated. Do not delete that exception to meet the ticket's one-line switch target.

For batch, create `Sources/SpeakCore/BatchTranscriptionRouting.swift` with immutable Sendable route metadata: normalised catalogue ID, provider/credential owner, API model name, and transport category (Apple local, direct provider, OpenRouter). Keep endpoint URLs and transport construction in their existing clients. Use exact catalogue constants and provider model sets, not an unrestricted prefix classifier. OpenRouter-wrapped IDs retain the downstream model mapping already used by OpenRouter helpers; a `google/` prefix alone cannot determine credentials.

Current platforms intentionally differ. `IOSBatchTranscriptionRoute.route` recognises only exact Apple/OpenAI/Cartesia/Gladia/Azure/Meta/direct-Gemini/xAI IDs and falls back to OpenRouter for everything else. Mac `TranscriptionProviderRegistry.provider(forModel:)` checks its registered provider's supported IDs, except an empty catalogue claims any ID under that prefix; it is also used for credentials/live ownership. A single unqualified batch route cannot preserve both unknown-ID behaviours. Make this explicit, rather than quietly normalise them into one new policy.

Recommended bounded contract: `BatchTranscriptionRouting.route(for:platform:) -> BatchTranscriptionRoute?` with a small `BatchTranscriptionPlatform` enum `.macOS`/`.iOS` and documented compatibility rules. This is one pure ownership policy with platform availability data, not a second transport factory. Avoid inventing an extensible capability framework. A platform-independent catalogue ownership helper may serve the implementation, but do not expose redundant public APIs just to match the ticket's sample signature. New public APIs need tests; existing public routing/factory signatures remain unchanged.

This may require two small PRs: batch ownership now, final live table removal after all folds. Record remaining adapter exceptions rather than making ticket checkbox counts dictate runtime behaviour.
