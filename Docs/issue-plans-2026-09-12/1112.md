## Scope and observed behaviour

Read AGENTS.md, README.md, the design guidance, reviews/1112.json and the landed prerequisite diff. Work on an isolated branch. The existing Mac controller already uses `SpeakCore.DeepgramLiveClient`; there is no Mac transport to retire. Change `Sources/SpeakCore/DeepgramLiveClient.swift`, its `DeepgramLiveProtocol.swift` extension, options/factory forwarding as necessary, `Sources/SpeakApp/SwitchingLiveTranscriber.swift`, and finally delete `DeepgramLiveController.swift`. Keep the batch provider, `createLiveTranscriber` if surviving callers require it, API-key validator, public client methods and all TTS code.

Current dedicated capture is mono PCM16 at 16 kHz, converter drain followed by `liveStopGracePeriod`, then immediate transport stop. It returns final segments plus outstanding interim, capture duration and estimated cost. Contrary to the review's wording, segments have start/end zero, not provider timestamps. Preserve this actual contract; adding accurate timestamps is optional separate work. The dedicated controller emits no utterance-boundary callback and no confidence updates. Its tap requests 1024 frames versus the shared controller's 4096; measure perceived partial latency on device, and only introduce a common capture-buffer option if parity requires it. Deepgram currently accepts arbitrary converted PCM chunks; do not copy other providers' 100/50 ms framing or silence padding without a demonstrated requirement.

## Mandatory provider shutdown correction

Current `finishAndWait` returns on the first final or Metadata, and stores finals only. Routing straight to it loses later finals or interim tails. Use one per-session state owner, ordered audio/control sends and an exactly-once shared finish result, following the earlier clients' minimal lifecycle approach. Preserve existing public initializers and `sendAudioSamples`; add forwarding overloads rather than replacing exported signatures with default-argument variants.

Primary protocol verification on 2026-09-12:

- [Nova CloseStream](https://developers.deepgram.com/docs/close-stream) flushes cached audio, sends results, then summary Metadata and closes. An ordinary `is_final` result is not stream completion.
- [Flux CloseStream](https://developers.deepgram.com/docs/flux/close-stream) emits outstanding `Update` messages and closes; it does not emit EndOfTurn or summary Metadata. The docs explicitly describe a close without a WebSocket status code. Therefore a Nova Metadata waiter cannot implement Flux finish, and the latest Flux Update must survive close as recovered stream text.

Keep the existing JSON text `{"type":"CloseStream"}` for both. Do not add ForceEndTurn, change VAD, endpoint parameters or model defaults in this fold. Finish sequence:

1. Atomically freeze new capture admission and capture run identity. Shared capture stops its tap and drains queued converter work before calling finish. Flush existing bounded preroll into the same ordered send path as ordinary PCM; ensure preroll flushes upon readiness without requiring another capture chunk. Preserve its current cap/eviction policy.
2. Bound accepted PCM-send completion before CloseStream; a DispatchGroup alone cannot order concurrent sends. Send CloseStream after all admitted audio, with its own bounded send failure/stall handling. No control frame overtakes audio. With no running socket, resolve promptly with recovered text and release resources.
3. Keep decoding every accepted frame during shutdown. Nova resolves at this run's post-close Metadata or socket termination; Flux resolves at socket termination, retaining the latest active-turn Update. Neither finishes on the first final. On bounded timeout/error/cancellation, preserve all confirmed text and the last valid pending interim. A normal expected Flux stop closure must not become a spurious user-facing transcription error; an unexpected mid-recording failure still does.
4. Retain the existing one-second provider drain budget initially, exposed through the common options only if needed. Preserve user grace explicitly: add the configured grace to the permitted receive window, without a redundant unconditional sleep after definitive terminal closure. Capture duration excludes these network waits. Tests define the total bounded deadline, including send drain; do not leave a send completion able to hang forever.
5. `stop()` stays prompt abort/cleanup and resumes all waiting finish callers once. Every receive, timer, send completion and parser mutation checks captured session/socket identity. Restart cannot receive an old timeout, clear new text or close a new socket. Do not invoke callbacks or continuations under locks.

## One snapshot and existing boundary capability

Reuse `StreamingTranscriptSnapshotProviding.transcriptSnapshot(captureDuration:)` and `StreamingTranscriptSnapshot`, including any compatible additions landed by #1111. Track confirmed standalone finals and active interim separately. Clear only the interim replaced by its final; preserve legitimate identical text in different turns. For Flux decode optional `turn_index`/`sequence_id` if required to distinguish stale updates or duplicate same-turn finals, retaining legacy minimal fixtures. Identity-based corrections are safer than text deduplication; Nova finals with no identity preserve arrival-order semantics.

Snapshots expose nonnil confirmedText (including empty), pendingInterim, zero-time final segments and estimated cost from the supplied captureDuration. A final result includes surviving pending text exactly once but does not manufacture a confirmed segment for a timeout interim. Keep confidence/rawPayload nil as before. The shared controller captures event snapshots before its MainActor hop and the final snapshot before releasing the client; no Deepgram-specific branch belongs there. Preserve legacy callback final shape `.standaloneSegments` and existing no-double-delivery finish contract: internally consume trailing finish finals without replaying them as additional final callbacks, while retaining all of them in the returned full text.

Move the pure `estimateDeepgramCost(durationSeconds:model:)` calculation beside the client or a focused core helper. Preserve its existing estimate branches exactly: Nova-3 0.0077 USD/min, other Nova 0.0058, enhanced 0.0165, base 0.0145, fallback including Flux 0.0077; nonpositive duration nil; inputTokens remains Int(seconds). These are existing application estimates, not a claim about current provider prices. Changing rates/catalogue pricing requires separate verified work. Reuse an identical canonical existing helper if inspection finds one; avoid two estimates.

Conform to the upstream explicit boundary capability with no events, preserving dedicated Mac behaviour and suppressing the shared cumulative-final fallback. Enabling Deepgram utterance-driven polishing or exposing confidence/timestamps is optional separate work, not required parity.

## New consumer compatibility (main 2ff982d, PR #1102)

Before implementation, inspect `Sources/SpeakApp/CompareModels/ComparisonLiveLane.swift` and `ComparisonLiveFanOut.swift` on the current base. ComparisonLiveLane calls the legacy factory overload with keywords/azureEndpoint, accumulates according to `client.finalShape`, then REPLACES its transcript with `finishAndWait`'s full-session return under an outer timeout of at least eight seconds. Fan-out feeds PCM by route sampleRate and drains capture before finishing lanes concurrently. Preserve that overload, callback shape, complete-return semantics, cancellation and idempotent stop for this consumer too; shared Mac-controller tests alone cannot establish compatibility. Keep optional snapshot/boundary capabilities optional and do not require callers to adopt them to retain existing text. Add/extend existing Compare Models lane/fan-out regression coverage for affected finish behaviour; avoid a separate capture framework. A provider's bounded finish must cooperate with lane cancellation rather than leave abandoned work alive.
