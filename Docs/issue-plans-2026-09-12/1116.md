Decision: NARROW; SOL medium after #1115 extraction lands. Prevent credential omissions while preserving storage identifiers, consent, observable UI and existing transfer compatibility. Read reviews/1116.json and the actual #1115 paths/diff; its 17-key count describes persisted local settings, not a newly assumed number of provider credentials. No CloudKit container change (#1119), SettingsSync deletion or transfer-format expansion.

## Canonical credential catalogue

Create `Sources/SpeakCore/ProviderCredentialCatalogue.swift` containing immutable Sendable credential entries and explicit policies. Minimum entry identity is stable credential identifier plus provider ID; add purpose only where needed to distinguish `openai.apiKey` from `openai.tts.apiKey`. Preserve all existing known bytes. The existing config-transfer list in `SettingsSync.swift` is a useful complete baseline of 18: assemblyai.apiKey, azure.speech.apiKey, cartesia.apiKey, deepgram.apiKey, elevenlabs.apiKey, gladia.apiKey, google.apiKey, groq.apiKey, meta.apiKey, mistral.apiKey, modulate.apiKey, openai.apiKey, openai.tts.apiKey, openrouter.apiKey, revai.apiKey, soniox.apiKey, speechmatics.apiKey, xai.apiKey. Search current production/fixture/catalogue consumers before fixing this list; additional genuine existing credentials need an explicit supported-purpose entry, not silent exclusion.

Expose a known-provider lookup returning an optional entry/identifier, a deterministic deduplicated `all`, and explicit projections for current transferable and CloudKit-syncable policy. Do not derive `all` from runtime registration, which could export arbitrary dynamically registered secrets. Do not implement Azure as `azure.apiKey`; reuse `AzureSpeechConfiguration.credentialIdentifier` to prevent a cycle/second literal owner. Keep OpenAI TTS purpose distinct even where live/STT use the primary key. Local Apple has no credential.

`CloudKitKeySync.syncableIdentifiers` is public `Set<String>` and must remain that signature. Forward it to a catalogue Set with exactly the current twelve identifiers: deepgram, openai primary, openrouter, elevenlabs, cartesia, assemblyai, gladia, google, modulate, soniox, xai and meta. The broader list does not authorise adding Azure/Groq/Mistral/Rev.ai/Speechmatics/OpenAI-TTS to automatic key sync. Forward public `ConfigTransferManager.transferableSecretIdentifiers` to the existing ordered eighteen-key projection with its old type. Preserve sync enablement, pending changes, secret deletion, errors and encryption entirely.

Replace production credential-name ownership in `StreamingTranscriptionClient.swift`'s `LiveTranscriptionProviderID.apiKeyIdentifier`, `VoiceOutputSettings.swift`, transferred credential lists, extracted iOS AppSettings key constants, and applicable Mac provider metadata/key resolvers. `TranscriptionProviderMetadata` has an existing default initializer constructing `id.apiKey` and an explicit identifier initializer; preserve both exported signatures and legacy fallback for unknown/custom IDs. Known Azure metadata must keep its explicit override. Public generic metadata construction must not unexpectedly become failable.

Use catalogue lookups where the consumer really refers to these credentials. Keep fixtures' literal baseline values independent so tests detect accidental renames; no grep-zero requirement. Never log keys or enumerate unrelated Keychain secrets to satisfy parity.

## Preserve iOS observation and UI ownership

Use the `AppSettings.swift` and `APIKeysView.swift` paths established by #1115, not the original 3159-line SettingsView. Retain existing published per-provider properties and key constants as forwarding compatibility members. The ticket's dictionary rewrite is optional and excluded from this first change: it touches bindings, initial async load, selected-model fallback, key availability sets, keyboard configuration, migration and error handling without being necessary to centralise identifiers.

Project credential row identity through the catalogue with deliberate iOS-supported-provider filtering, but preserve existing row order/display text, website links, secure text toggles, validation state and special inputs. Do not show every transferable credential merely because it can be held for another platform. Azure region/resource configuration remains its specialised adapter; do not replace it with a generic one-field row. Mac's registry-driven API key UI keeps its metadata ownership and provider validation. Catalogue entries do not become a competing UI/provider registry.

Loading must still wait for the same initial key-load task; existing `persistSecret` suppression during load and write/remove failure presentation must remain. Updating/deleting a displayed key must affect the same published property, same identifier and same keyboard/profile notifications as before. Keep legacy credential migration and Google-specific key behaviour intact. If changing row iteration cannot be made small without dictionary storage, keep row structure and change only the identifier projection in this patch; this still delivers the accepted seam consolidation.

## Shared settings: same name is not same semantics

Add `Sources/SpeakCore/SharedSettingsKey.swift` only for fields proven equivalent by reading both accessors/default initialisation and consumers. The initial safe candidates are existing string-valued `batchTranscriptionModel`, `postProcessingModel`, `transcriptionKeywords`, `preferredLocale`, and Boolean `postProcessingEnabled`/`handsFreeDictationEnabled`; verify their stored representation and side effects before including each. Keep defaults platform-owned: sharing the name does not make model availability, hands-free gating or default values identical. Existing `LiveTranscriptionSelection.DefaultsKey` remains the owner of its two remembered-selection keys, not a duplicate enum.

Keep selectedModel versus liveTranscriptionModel, transcriptionMode, silenceDetectionEnabled versus autoStopOnSilenceEnabled, silenceDuration versus autoStopSilenceSeconds outside this patch. Their model placement/mode/trigger behaviour and types require explicit mapping, and choosing iOS spelling based on install counts has no evidence. There is no key migration in the minimal patch because accepted shared names already match.

Preserve each platform's existing DefaultsKey cases and `.rawValue` compatibility. If adopting shared values cannot be expressed as Swift enum raw-value literals, add an internal `storageKey` projection forwarding the accepted cases to `SharedSettingsKey` and the remaining cases to existing rawValue, then update the actual UserDefaults read/write helpers and direct persistence sites to use it. Test equality to old raw bytes. Do not attempt `case x = SharedSettingsKey.x.rawValue`, which Swift forbids as a nonliteral enum raw value. Avoid broad accessor/property-wrapper redesign. The #1115 exact 17-key test remains valid.

No widening of `transferableSettingKeys`: `ConfigTransferPayload.settings` is `[String:String]`, gather/import explicitly understand only selectedModel and keywords. A whitelist of Bool/Double defaults is not a typed transfer. Preserve versioned encryption/QR capacity and platform-specific `liveModelDefaultsKey` mapping. Future typed transfer needs separately reviewed schema/version/import validation and old-client tests. Keep public `SettingsSync`, its notification and tests: `SyncAvailability.current` and `SyncStatus.current` call `.shared`, and status reads lastSyncDate. No `!` title or API-break allowlist entry is justified by this scoped refactor.
