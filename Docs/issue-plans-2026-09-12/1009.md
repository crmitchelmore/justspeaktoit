# #1009 implementation plan: explicit trailing commands for local delivery

Decision: NARROW, SOL medium. Implement a default-off deterministic English command option for clipboard and historyOnly only. No Notes/Reminders/Mac/agent executor, LLM routing, phrase editor or external Undo. Base on current #994/#996/#999 service/settings/history paths, preserving TranscriptClipboard and strict-local model policy. The parser operates on the finalized capture, never on partial text.

## Grammar and pure policy

Add Sources/SpeakCore/SpokenRoutingCommand.swift containing a pure parser and immutable result: originalText, contentText and optional recognized destination/command metadata. It executes no effects and does not depend on UIKit. Support exactly these final command clauses, case-insensitive with surrounding whitespace and one terminal sentence punctuation mark tolerated:

- `Speak command: just copy` → clipboard, suppress polish.
- `Speak command: save to history` → historyOnly.

Allow a comma or sentence boundary before the trigger and whitespace around its colon; document the mandatory distinctive trigger. Do not accept bare “just copy”, “to Notes”, “to Mac”, approximate words, missing trigger colon, synonyms, or commands in the middle. The trigger and command must be the complete final clause, preceded by nonempty content. Support an explicit literal escape: a final `Speak literal` clause disables routing for the entire capture and is itself preserved verbatim. Exact quoting of the trigger/command, unbalanced quotes, multiple trigger occurrences, repeated/different commands or empty derived content all return original text unchanged. A trailing escaped sample remains fully recoverable, including the escape words; no hidden character stripping.

Enable parsing only when the per-capture setting snapshot is on and the effective resolved language is explicitly English (`en` or a canonical English language identifier). Unknown/auto language or other languages are literal. Determine locale from the effective capture configuration, not the device UI locale; do not add automatic language identification. Preserve original Unicode spelling/whitespace byte-for-byte in originalText; trim only the recognized command boundary from derived content. Tests are the authoritative grammar and cover straight/curly quotes, punctuation, multiline whitespace, mixed case, apostrophes in normal content and malformed final clauses.

## Settings and destination provenance

Add one local Boolean DefaultsKey/property `spokenRoutingEnabled`, default false, to extracted Sources/SpeakiOS/Settings/AppSettings.swift and a native toggle with both exact examples, English limitation and literal escape in the existing destination settings section. Preserve the existing 20 keys from #994; this explicit addition makes 21 if no other independent additions have landed. Assert the original mapping plus named new entries rather than a stale total. Exclude this behavioral consent setting from ConfigTransfer and sync. Snapshot enablement/language at start so changing Settings during capture cannot newly strip text.

Add a small internal `CaptureDestinationSelection` value (destination plus origin) beside the service or existing capture parameter helpers. Origins distinguish explicitStop, explicitStart, keyboardProfile, focus (when #1014 is present), spoken, global and legacy. Reuse this value in #1014; do not build a second router. Keep public CaptureRunParameters and resolvedStopDestination(explicit:) signatures and behavior compatible. Audit all internal stop callers: several resolve a global destination first and pass a non-nil enum, which loses its origin. Carry actual origin through a new internal overload/helper. Retain the old public stopRecording call shape forwarding non-nil destination conservatively as explicit; do not infer provenance from enum equality.

Precedence for this feature is explicit Stop, existing explicit Start/keyboard-owned choice, active frozen Focus destination if #1014 is installed, recognized spoken command, then global/legacy default. Higher-priority destination suppresses interpretation and preserves command words. Keyboard-owned nonce/profile capture retains its field-delivery contract and is excluded from this first parser integration; ordinary phone-service captures may use spoken commands. Focus above spoken is deliberate: a privacy override must not be silently defeated by a phrase. Explicit Stop remains an intentional escape. Disclose this precedence in the setting help.

## Resolve before every publication

Refactor the finalized section of Sources/SpeakiOS/Services/TranscriptionRecordingService.swift.stopRecording, immediately after drain and latestCompletionID validation, before clearing currentRunParameters, completeRun, History, keyboard publication or any external write. Capture the ending run’s selection/context before resetting it. Compute one immutable delivery decision: original text, content, destination origin, keyboard eligibility and polish policy. Propagate derived content consistently through returned TranscriptionResult, run completion, partialText/wordCount, shared completion/handoff, clipboard and receipt. Provider timing/confidence metadata remains unchanged; do not pretend returned segments omit command words unless they are actually adjusted. Keep the original provider result available locally where necessary rather than fabricating segment alignment.

A recognized history command MUST suppress KeyboardDeliveryPublisher.publish as well as clipboard/polish, including late pickup offers. A just-copy command also suppresses keyboard publication and legacy autoPostProcess, producing exactly one policy-controlled clipboard write. Do not wire parsing only into applyDestinationSideEffects: the current code publishes keyboard offers earlier. Existing .auto publication/claim/fallback behavior for unrecognized or disabled captures stays unchanged. Empty finalized captures cause zero writes. Duplicate stops and cancellation during drain retain current run fences.

Preserve a durable original before stripping content. Add an optional local `originalTranscription` field to iOSHistoryItem in Sources/SpeakiOS/Views/iOSHistoryModels.swift, absent by default and decoded with decodeIfPresent; existing transcription stores delivered content and postProcessedTranscription retains its existing meaning. Extend existing history construction with a retained old overload, not a changed exported signature. Set originalTranscription only when a command is applied. Keep this local metadata out of SyncableHistoryEntry’s nine-field wire projection and document that existing History itself can sync delivered content. Coordinate #1118’s local-record adapter to preserve this extra field; no storage migration or new journal.

If saveToHistory is false, leave command words literal because this scope cannot promise original recovery. If a recognized route’s original cannot be retained by the current durable History/recovery path, suppress publication/clipboard/keyboard, preserve the full original in the existing failure/recovery result, and report truthful persistence failure using #996’s safe presentation. Do not fall back from requested history-only to clipboard. No “Saved” receipt without durable evidence.

In HistoryView/HistoryItemRow’s existing detail/copy actions, expose “Copy original” only for routed records using TranscriptClipboard.shared, and label displayed delivered content clearly. Do not overwrite originals during polish, edits, retries or sync reconciliation; the optional original survives local updates. The feature promises recovery/copy, not reversal of another app’s insertion. Use existing resolved receipt/outcome wording; do not add raw command telemetry or unearned destination claims.
