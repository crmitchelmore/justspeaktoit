# #1117 implementation plan: complete the recording-service dependency seam

Decision: NARROW; SOL medium. Make recording start, stop, delivery and recovery independently testable using the existing initializer. No app-wide environment, view migration, Watch module move or mutable singleton bootstrap. Read reviews/1117.json, AGENTS.md and landed #1115/#1116 interfaces. Work on an isolated branch; preserve native recording ownership and existing entry points.

## Existing seam and concrete changes

`Sources/SpeakiOS/Services/TranscriptionRecordingService.swift` already injects sharedState, historyManager, clipboard, polish/key/load closures, sessionFactory, completion sink and foreground ownership. Keep these arguments and existing tests. `static let shared` remains safely initialized by the private convenience initializer; app delegate, intents and background push paths cannot depend on SwiftUI having bootstrapped a global. Keep the existing service instance and `ForegroundRecordingOwnership.shared` identity used by the foreground coordinator. Do not allocate a second production owner.

Add a small internal `RecordingServiceDependencies` bundle only for the missing collaborators if extending the existing signature becomes unreadable. Put it in a focused adjacent file if needed. MainActor isolation is appropriate for this service and injected UI collaborators; avoid unnecessary Sendable promises for mutable objects. Production construction is one named factory/default bundle, called lazily by the same convenience initializer. Do not start key loads, ActivityKit or Watch sessions merely to construct an unused bundle.

Inject the actual `AppSettings` instance. Replace global reads in batch-mode selection, `startRecording`, destination resolution (`adoptRunParameters`/hardware-trigger policy), automatic postprocessing settings and `shouldAutoPostProcess`. Pass that instance into existing `modelSelection`, credential-validation and session construction helpers. Preserve precedence: explicit run parameters/keyboard profile before settings. Keep `ensureKeysLoaded` tied to that same settings instance; do not pair an injected settings object with the global key-load task. After the awaited key load, the same lifecycle/run/foreground ownership checks must occur before microphone allocation. Read mutable settings at the same phase as current code rather than caching all settings at construction and changing mid-session semantics.

For ActivityKit, inject a narrow activity sink with the operations already called: start, update, end, reportError, and existing completeActivity. A small closure bundle or one internal protocol is sufficient; prefer existing manager methods directly if an isolated manager already supports testing. All operations must target the same chosen sink. `completeSharedActivity` can remain the production forwarding function; a test-supplied update sink must not secretly complete a real Live Activity through its default. Preserve payload values, keepPrimed behaviour, resultCompletionID, durations and completion outcomes.

Inject onboarding recordDictation and safety markDelivered as narrow closures or isolated existing stores. Mark safety delivery only after the same successful delivery point, using `deliveringSession.safetyRecordingID`; do not mark all pending recordings delivered at stop. Preserve cancellation/error handling and recovery journal semantics. Broad journal/telemetry plumbing is outside this issue unless a concrete existing test isolation problem demands a narrow seam.

Inject `KeyboardDeliveryStore` and pass it explicitly to both `KeyboardDeliveryPublisher.publish(...store:)` and `awaitOutcome(...store:)`; replace the availability read with the same store. These APIs already accept injection. If service tests need deterministic outcomes without 1.5-second polling, add two narrowly typed publisher closures in the bundle, preserving `KeyboardPickupOffer` and `CaptureReceiptBuilder.KeyboardOfferOutcome` rather than reducing outcomes to Bool. Test actual publisher separately with its existing suite. Publishing an offer is not proof of field insertion; only its claim/outcome can select the receipt lane. Preserve no-Full-Access behaviour, targeted-document constraints and clipboard fallback.

Use injected `historyManager.macLaneOutcome(for:)` when building `CaptureReceiptBuilder.Outcome`; the current `.shared` call contradicts the injected manager that created the row. Keep existing history record, begin/end postprocessing and error mutations on this same manager. Do not introduce Send to Mac delivery or change its current outcome semantics.

Inject `applicationState: @MainActor () -> UIApplication.State` for both start's foreground decision and `AutomaticPolishOperation.start(isActive:)`. The production closure reads UIApplication at invocation time; tests return a fixed/mutable fake value without modifying the process UI state. The adjacent background-assertion adapter already accepts begin/end closures; preserve and reuse that seam for expiration tests rather than adding another global wrapper. Retain existing `polish`, `hasPolishingKey`, `PolishClipboard` and sessionFactory injection; no new postprocessing manager protocol is necessary.

Keep the old internal designated initializer call shape as a forwarding overload/default bundle for existing test callers while allowing fully isolated construction. Public service APIs, `shared`, observed properties and recording methods remain unchanged. The default bundle must make dependency identity explicit; do not silently replace an injected object's callbacks with globals. A focused `TranscriptionRecordingServiceTestSupport.makeService` supplies isolated settings/defaults, history, ownership and no-op activity/delivery/safety sinks. It should not mutate production singleton state between tests.

## Behaviour-preserving tests

Extend `Tests/SpeakiOSTests/TranscriptionCompletionTests.swift` and `TranscriptionRecordingServiceTextTests.swift`, with focused new dependency tests if useful. Verify:

- Supplied settings choose model/mode/language/vocabulary/key/destination and postprocessing preference even when globals differ; a blocked injected ensureKeysLoaded delays session creation, and cancellation/foreground claim during the wait prevents allocation.
- Receipt construction queries the injected history manager, preserving durable versus in-memory outcome and existing Mac-lane status; delayed polish updates only the injected original row.
- Fake activity operations receive start/update/error/completion for one run and never a previous completionID. No real ActivityKit work occurs in isolated tests.
- Keyboard inserted/late-pickup/unavailable/timed-out outcomes preserve automatic destination/clipboard receipt choices; supplied store is used for availability, publish and confirmation together.
- Safety delivery receives the exact successful run's recording ID and is absent for cancelled/undelivered captures. Onboarding is recorded at the same valid-transcript point as before.
- Application active/background cases choose the same assertion/activity/clipboard flow while tests avoid UIApplication global mutations. Rapid restart or delayed completion cannot affect the replacement run.

Retain `InterruptionFinalisationTests`, `ForegroundRecordingCoordinatorTests`, `ForegroundRecordingIntentOwnershipTests`, `RecordingLossOwnerLifecycleTests`, `RecordingLossReportingTests`, `AutomaticPolishOperationTests`, `KeyboardDeliveryPublisherTests`, `CaptureSafetyClaimStoreTests` and existing receipt/delivery tests. Reuse existing fixtures and seams. Do not write a bootstrap-does-not-crash test as a substitute for asserting actual dependency effects. Source searches should show no operational AppSettings/history/store global reads in this service outside the named production construction/forwarding path; zero `.shared` throughout the app is not an acceptance goal.

## Integration and native gates

No edits to `SpeakiOSApp/SpeakiOSApp.swift` delegate launch ordering, background history handler, extension bootstraps or the views are required. Their safe static entry paths and direct observation stay in place. If a tiny caller must pass the new bundle, preserve one existing service/ownership identity and explain why; avoid cascading unrelated initializer changes.

Run diff checks, native Apple lint, iOS build-for-testing/SpeakiOSTests and normal required macOS/core CI for shared changes. Run public API compatibility against the PR base; a breaking `!` title is unnecessary because no public removal is authorised. Linux inspection does not prove Apple concurrency or lifecycle behaviour.

Device acceptance: cold launch, foreground recording, hardware/intent recording from background, stop/interruption, final transcript in History, keyboard/clipboard receipt and delayed polish; verify no competing foreground/headless capture and no spurious Live Activity. Use an existing authorised device/account, no new paid credits. Record unavailable hardware/device gates honestly. Submit a scoped PR identifying eliminated global reads and the tested outcomes. Broader composition/view migration remains deferred until a concrete ownership/observation problem justifies it; this plan does not require #1116's optional redesign to proceed.
