# #1016 implementation plan: authenticated structured transcript output

Decision: NARROW, SOL medium. Add a local History entity and a NEW Get Last Transcript action returning it. Keep GetLastTranscriptionIntent, StopDictationIntent, DictateIntent and every saved String Shortcut contract unchanged. No indexing/donation, interactive snippet, Stop/Dictate entity variant, remote sync entity, Copy action, Notes workflow or Send to Mac. Base on current #994/#996/#999; coordinate #1009 optional original text and #1118 local History adapters without waiting for their full refactors.

## Entity projection and stable identity

Add Sources/SpeakiOS/Activity/TranscriptEntity.swift with a small AppEntity value and identifier query. Keep iOSHistoryItem in Sources/SpeakiOS/Views/iOSHistoryModels.swift as the storage model; do not make the persisted record itself conform or change on-disk encoding. Use the existing History UUID as entity ID, never capture completion ID, array position or a new generated UUID. No CloudKit lookup/network request belongs in this projection.

The entity exposes localized Shortcuts properties for optional raw text, optional polished text, creation date and optional duration seconds. For a populated authenticated result, raw text is the original captured text when #1009’s originalTranscription exists, otherwise the existing transcription field. Polished text is the exact nonempty stored postProcessedTranscription; blank-only values map to nil. Do not silently substitute polished text into rawText. Creation date is the stored date; duration comes only from a finite nonnegative stored value. Do not invent source device, infer phone identity from originPlatform, or fabricate absent metadata for old entries. If a text property is intentionally unavailable in a query projection, nil means unavailable; empty text is not used as a fabricated transcript.

Use a content-free DisplayRepresentation such as “Transcript” with a localized creation date. No transcript prefix, source tag, model/provider or error description appears in titles/subtitles/synonyms. Define typeDisplayRepresentation and defaultQuery using existing supported App Intents syntax. Apple’s [AppEntity](https://developer.apple.com/documentation/appintents/appentity) and [EntityQuery](https://developer.apple.com/documentation/appintents/entityquery) metadata show iOS 16 availability, compatible with this app’s iOS 17 target. Verify property wrappers and generated metadata on the actual shipping Xcode SDK; no iOS 26/27 APIs are required.

## Authentication boundary: queries are not authenticated actions

`IntentAuthenticationPolicy.requiresAuthentication` applies to the new action. Do not assume it automatically protects EntityQuery invocations initiated separately by Siri/Shortcuts. Therefore `TranscriptEntityQuery.entities(for:)` returns only content-free projections for explicitly supplied existing identifiers: UUID/date/known duration, with rawText and polishedText nil. `suggestedEntities()` returns an empty array; no default latest value, free-text matching, enumerable query, searchable keywords or donation is added. This makes the initial entity useful as a structured authenticated action result without silently exposing text during background identifier resolution.

Use the existing local History reader on MainActor, with an injected snapshot closure for tests and await readiness if #1118’s async entry point has landed. For known IDs, preserve requested order, deduplicate repeated IDs and omit deleted/missing IDs; never replace a missing identifier with the newest transcript. If protected storage is unavailable, return a safe failure/empty query according to the existing History readiness contract rather than asserting no History exists. A protected-data check is only a storage safeguard, not proof the user authenticated this query.

If later saved entity rehydration must repopulate private properties, it requires an explicitly authenticated retrieval action or a separately verified framework authorization mechanism. Do not cache “recently authenticated” globals, add Face ID prompts to suggestion enumeration, or populate query text just because the phone has been unlocked once. Document this deliberate initial limitation: properties are populated on the new action’s returned value; passive identity resolution contains no transcript. A result already deliberately handed to Shortcuts may be stored by that Shortcut; app deletion/locking cannot promise to retract it.

## New action and backwards compatibility

Add `GetLastTranscriptEntityIntent` in a focused Activity file, with user-facing title “Get Last Transcript” and a description distinguishing structured properties from existing “Get Last Transcription” text output. Set openAppWhenRun false and authenticationPolicy requiresAuthentication. Its perform returns `some IntentResult & ReturnsValue<TranscriptEntity>` using a populated projection only after the framework enters the authenticated action. Keep default discoverability needed for the Shortcuts action; do not add AppShortcut phrases that automatically suggest transcript content.

Reuse the existing GetLastTranscriptionIntent selection algorithm: load local History, choose the first entry in its established newest-first order for which AutomationIntentSupport.bestTranscript(raw:polished:) is nonempty. Select the entire row once, then project that UUID’s fields; never choose raw and polished from separate mutable “latest” reads. Do not wait for an unrelated ongoing polish or trigger a provider request. A raw-only row is valid; the user can branch on polishedText availability. Empty History/no useful text throws the same safe noTranscriptionYet error. Storage failure remains a storage failure, mapped through #996 rather than indistinguishable emptiness.

Preserve original String action declarations, identifiers, optional Wait For Polish parameters, authentication and keyboard ownership. Do not call CopyFullTranscriptIntent, which reads mutable SharedTranscriptionState.currentTranscriptText and could copy a newer capture. No clipboard write occurs in either query or new action; downstream user-chosen Shortcuts actions are outside this app’s delivery claim. If an app-owned copy action is added later, it must bind an entity ID and use #994’s policy writer.

Guard entity payload size before returning full text. Apple’s AppEntity documentation currently specifies a total entity size limit; use a conservative small local byte budget for combined UTF-8 text and metadata, with a clear “Transcript too large for structured output; use Get Last Transcription” failure. Never silently truncate transcript properties or add a newer deferred-property API just to avoid that bounded check. Unit-test the boundary with synthetic content, not private History.
