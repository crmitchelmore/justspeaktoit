## Implementation sequence

### 1. Finish options integration, without changing routing

Inspect the #1104 implementation: its required-options factory is `makeClient(for:apiKey:language:options:azureEndpoint:)`; the old two keyword overloads remain forwarding shims. AssemblyAI has the exact original `init(apiKey:speechModel:sampleRate:session:)` plus a new overload ending in required `keyterms: [String]`. Keep BOTH exact signatures, defaults and `URLSession?` injection, forwarding to another designated overload that requires a finish-settings argument. Adding a defaulted parameter to an existing public signature is not symbol compatibility. Its shared request builder already receives keyterms for both hosts; reuse that work.

Extend `LiveClientOptions` with `postStopFinalizeBudget: TimeInterval?` (nil means provider default) and `stopGracePeriod: TimeInterval` (zero by default). Preserve its exact three-argument public initialiser as a forwarding overload; use a new overload with a required timing argument to avoid ambiguous all-default overloads. Add a small macOS-only settings projection, e.g. `AppSettings.liveClientOptions`, in a focused extension or existing settings extension: parse generic keywords through the existing keyword helper, parse `assemblyAIKeyterms` like the old controller, map all four Modulate settings, and snapshot `liveModelCapabilities.postStopFinalizeBudget`/`liveStopGracePeriod`. Pass it from `SharedClientLiveController.start()` instead of the `.meta/.google` conditional. The controller must have no provider-specific options branch. The factory uses timing fields for AssemblyAI only in this issue, avoiding incidental behaviour changes for other providers.

Carry a snapshot of the selected route's finalisation budget and user grace into the client. The current catalogue gives AssemblyAI 2 seconds; derive that default from `ModelCatalog.liveCapabilities(for:)`, not another independent model catalogue. A legacy call without options must still get a safe AssemblyAI finish budget. Sanitise nonfinite/negative stop values and respect the existing user-setting range. Do not read `AppSettings` or `UserDefaults` from SpeakCore.

### 2. Add narrow, optional provider-neutral contracts

In `Sources/SpeakCore/StreamingTranscriptionClient.swift`, reuse #1104 equivalents if present; otherwise add optional capabilities:

- `UtteranceBoundaryStreamingTranscriptionClient`: a callback property (or equivalent registration method) delivering the provider's standalone utterance text. The shared controller registers it before `start`, captures weak client/self, marshals to MainActor and verifies `LiveTranscriptionRun.isCurrent`. Providers that do not conform keep their existing final-based behaviour.
- `StreamingTranscriptSnapshotProviding`: one optional capability with `func transcriptSnapshot(captureDuration: TimeInterval) -> StreamingTranscriptSnapshot`. Add the small public `Sendable` snapshot struct with immutable fields/defaulted initializer: `confirmedText: String? = nil`, `pendingInterim: String? = nil`, `segments: [TranscriptionSegment] = []`, `latestUpdateConfidence: Double? = nil`, `confidence: Double? = nil`, `duration: TimeInterval? = nil`, `cost: ChatCostBreakdown? = nil`, `rawPayload: String? = nil`, `isTerminal: Bool = false`. These are concrete parity needs across reviewed AssemblyAI/Cartesia/ElevenLabs/Gladia/Modulate folds, not separate field protocols. Only AssemblyAI conforms in #1105.

Snapshot semantics: nonnil `confirmedText` plus nonempty `pendingInterim` is the complete Mac display/result text, with the existing space joining; the interim stays unconfirmed and outside segments. Nil `confirmedText` means no text override, preserving normal callbacks/finish return. `latestUpdateConfidence` belongs to the current callback event; `confidence` is final aggregate result confidence. Optional duration/cost/rawPayload override controller defaults. `isTerminal` reports a transport that has definitively ended; it defaults false and enables later Modulate terminal-error capture cleanup without another capability. #1105 does not change general error handling. `captureDuration` supplies actual controller duration for provider fallback calculations (needed by Modulate) without importing settings/platform clocks into SpeakCore. AssemblyAI provides finalised text, outstanding interim and segments; confidence/duration/cost/rawPayload remain nil.

The shared controller retains the finishing client, snapshots after finish, uses any explicit text override for result/display without promoting interim to confirmed, and merges optional result fields with existing defaults. Never append the snapshot interim onto latestTranscript: that may already contain it. Capture the optional snapshot synchronously inside each ordinary transcript callback using captureDuration zero (only text/event confidence are consumed there), before hopping to MainActor, so event confidence/text projection is immutable for that update. A conforming client serialises parser mutation and callback delivery so no later event can overtake that capture. Shared controller then uses snapshot text/confidence when provided, otherwise legacy event values. Preserve callback isFinal and stale-client guard; don't register another callback that duplicates events. Required start/finish signatures remain unchanged. The explicit boundary capability stays separate because it delivers events. No rich-update or per-field metadata protocols. This contract also lets later Modulate snapshots provide formatted Mac text while iOS keeps its existing legacy raw callbacks.

Snapshot tests in #1105 cover nil defaults, explicit empty confirmed text, pending interim not duplicated/promoted, preserved segments, and generic legacy-provider fallback. Do not introduce a different snapshot framework in later folds.

Do not change required `StreamingTranscriptionClient.start` or `finishAndWait` signatures. Add `FinalizingStreamingTranscriptionClient` conformance to AssemblyAI and keep `finishFlushesBufferedAudio = true`. Its return must be the complete session transcript, never one final turn. Keep cumulative display callbacks (`isFinal=false`) for compatibility with existing consumers; capture/consume stop finals internally rather than also delivering the trailing final through `onTranscript`.

### 3. Move framing and finish state into the shared AssemblyAI client

Use a small internal PCM framer helper in `AssemblyAILiveClient.swift` or a focused `AssemblyAIPCMFramer.swift`; it need not become a public cross-provider audio framework. Derive bytes from configured sample rate, two bytes/sample, and 50/100 ms duration. Accept arbitrary PCM chunks, emit 100 ms frames in byte order, retain a residual, and on finish pad a nonempty residual to at least 50 ms. Do not emit silence for an empty stream; no frame exceeds the provider's documented repository bound (1,000 ms). Preserve all input bytes in order and use bounded buffers rather than repeated whole-buffer copying per chunk.

Protect session state with one clear lock/serial ownership scheme. Never invoke arbitrary callbacks or resume continuations while holding the state lock. Audio, pre-Begin draining and stop controls need a single ordered send path with completion accounting; a DispatchGroup alone does not order concurrently enqueued frames. Use per-session send state so an old send completion cannot release or fail a newer session.

`finishAndWait` sequence:

1. Atomically enter finishing, snapshot session identity, reject newly arriving capture audio, and arm completion state before any ForceEndpoint send (a final can arrive immediately). Share one finishing task/result for concurrent finish callers.
2. Flush the client's PCM residual. The shared controller already stops its engine/removes the tap and calls `audioProcessor.drainConverterTail(to:)` before invoking finish; that serial audio-queue barrier also drains queued tap conversions.
3. If Begin never arrived, close this run promptly, return existing text or nil, and do not wait a full model budget or create a fallback. Do not send pre-Begin binary audio or ForceEndpoint.
4. For a begun run, await completion of admitted audio sends, bounded by the existing 1.5-second drain limit. Then enqueue ForceEndpoint in that same send order. A send failure/stall must surface a bounded failure and close safely, preserving available transcript; do not silently claim all buffered audio was delivered. Control sends must themselves have bounded completion/cancellation behaviour.
5. Wait for a formatted end-of-turn received after finishing is armed, or the selected model budget. Consume it into the assembler and resolve the waiter exactly once. Keep receiving through the user grace period, applied after final/timeout and before termination, so late corrections still reach the returned full transcript.
6. Send Terminate only after ForceEndpoint/drain processing and grace. Use bounded Termination/close cleanup (existing maximum 3 seconds) without adding an unconditional extra delay after the final transcript is known. Snapshot the final full text and segments after the accepted grace frames; clean up only the captured session.

`stop()` remains the prompt abort/resource-release method for failed starts, cancellation and existing non-awaiting callers; it must resolve an active finish waiter and cancel that session's timers. `finishAndWait` is the only graceful-finalisation contract. Do not make a synchronous stop block MainActor.

Every receive/send completion, scheduled Begin retry, timeout, parser mutation and delayed close must check captured task/session generation. Pass the captured socket into the receive loop and message parser instead of looking up whichever socket is current when an old callback arrives. Preserve EU-first and one pre-Begin fallback without permitting old host callbacks to mutate the fallback's assembler or Begin state. `start` on a reused client cancels/resolves old state before resetting. Preserve the existing five-second pre-Begin cap and test its eviction policy explicitly; do not silently remove the cap.

### 4. Preserve turn and boundary semantics

Extend `AssemblyAIStreamingTurn` to decode optional `utterance`; keep typeless legacy Turn support. Deliver nonempty standalone utterance text before that message's display update. Preserve existing boundary behaviour rather than deduplicating genuine identical utterances based only on text. Late callbacks from old runs are ignored.

Extend `AssemblyAIStreamingTranscriptAssembler` with complete display/finalised-result snapshots as needed. Commit only when both flags are true. Replacing an existing `turn_order` must replace its existing segment; distinct turns with identical text both remain. Unformatted EOT stays interim. A current later interim must not be erased by a late correction to an earlier final turn; key interim ownership to turn order and test that ordering. Empty input returns nil, and timeout returns finalised turns plus the last valid outstanding interim with clean whitespace.

In `SharedClientLiveController.handleTranscript` and `applyFullTranscript`, suppress the fallback `didDetectUtteranceBoundary(displayText)` for clients that provide explicit boundaries. Otherwise the forced final return triggers polishing of the whole history even though an utterance was already sent. Preserve final and partial update delivery for generic consumers. Keep a local finishing-client reference through result creation so metadata/capability checks still work before clearing `self.client`.
