# #1014 implementation plan: a frozen Focus capture override

Decision: NARROW, SOL medium. Add one opt-in native Focus filter for existing destination/model/language fields. No profile builder, polishing setting, Send to Mac, agent routing or CloudKit configuration. Base on current #994/#996/#999 and reuse #1009’s destination-origin value if present. Keep capture ownership and existing public intent/parameter APIs.

## Native filter and reset contract

Apple’s [SetFocusFilterIntent](https://developer.apple.com/documentation/appintents/setfocusfilterintent) metadata identifies iOS 16 availability; current iOS 17 deployment suffices. Its [Focus sample](https://developer.apple.com/documentation/appintents/defining-your-app-s-focus-filter), read 12 September 2026 through official DocC JSON, explicitly describes deactivation invoking perform with default parameters. `SetFocusFilterIntent.current` is async throwing. Confirm these declarations with the supported Xcode SDK and actual metadata extraction; do not infer reset from scene activation or SF Focus status permission.

Add Sources/SpeakiOS/Activity/DictationFocusFilter.swift with `DictationFocusFilter: SetFocusFilterIntent`. Parameters are optional existing CaptureDestinationAppEnum, model and language, using CaptureModelOptionsProvider/CaptureLanguageOptionsProvider from CaptureIntentParameters.swift. Defaults must all mean “no override”, so a deactivation invocation clears state. DisplayRepresentation summarizes selected capture overrides without transcripts or an inferred Focus name. Configuration through Settings > Focus > Add Filter is the explicit opt-in; add a concise explanation and current effective override to existing app Settings, not a second hidden default-on switch. Do not request general Focus-status authorization to infer a selected filter.

Reuse existing App Intents metadata membership first. Apple’s sample uses an App Intents extension for background filters; this repository currently places intents in SpeakiOSLib. Compile and verify actual filter discovery/background perform delivery before adding target scaffolding. If the current supported architecture genuinely requires a dedicated extension, record the native discovery/execution failure and make that narrow target addition explicitly reviewable with existing App Group identity; do not introduce another capture process or broaden signing/provisioning by assumption.

## Local override store and validation

Add a small `FocusCaptureOverrideStore` under Sources/SpeakiOS/Activity, using the existing release-correct App Group suite from SharedTranscriptionState/KeyboardHandoffStore. Store one versioned Codable envelope with optional destination/model/language and generation; all-default perform removes the envelope. No transcript, Focus name, credential or cross-device sync. Separate key ownership from AppSettings’s original defaults; retain all 20 #994 defaults and subsequent explicitly added settings. Do not export this contextual selection through ConfigTransfer.

Use CaptureParameterResolution.resolve with CaptureModelSupport.vocabulary to validate configured overrides; no second provider catalogue. Validate again at capture time because model availability can change. If a supplied override is invalid/deleted, do not keep a previous valid filter or silently substitute a global/cloud model: store a bounded invalid-state reason and fail affected starts safely through #996’s mapping until reset or correction. Effective explicit fields may supersede corresponding invalid Focus fields; validate only the merged choice for fields actually used. Default reset always succeeds without requiring credentials.

Use a single authoritative writer path for perform and a generation-safe reconciliation helper. At capture start, reconcile the current native filter via `DictationFocusFilter.current` so a stale App Group snapshot cannot survive an undelivered reset unnoticed. Do not let a delayed read overwrite a newer perform update; serialize or compare store generation before applying it. On lookup failure, preserve the stored state for diagnosis and fail safely if an active/invalid override would otherwise affect capture. Do not silently clear a privacy-sensitive history-only choice into clipboard/global behavior. If no Focus override has ever been configured, ordinary capture should keep its existing behavior without acquiring an unrelated failure dependency. Add a visible reset/help path and test cold headless behavior. Do not invent an arbitrary expiry for a Focus that can validly remain active all day.

## One per-capture snapshot

Add a small immutable effective configuration/context alongside existing CaptureParameters helpers; it composes current validated CaptureRunParameters and records per-field origin. Preserve CaptureRunParameters exported initializers and optional semantics. Reuse #1009’s internal CaptureDestinationSelection rather than a parallel router. Source tags remain diagnostic and are not overwritten with a Focus name.

At start admission, freeze explicit inputs, the reconciled Focus snapshot and relevant global model/mode/language/destination. This snapshot belongs to the admitted run across awaited credentials and foreground-continuation retry; subsequent Focus changes affect the next run only. Keep lifecycle/foreground revalidation after each await. Field precedence is explicit intent/internal Start value > Focus value > global. A named Focus model counts as an explicitly selected model for mode derivation, capability/credential checks and #999 strict-offline policy; it must not become eligible for silent ordinary-model fallback. Empty parameters do not erase a higher-level value except the filter’s all-default reset.

KeyboardDictationProfileOption retains its existing complete ownership and nonce-bound field delivery; it ignores Focus parameters. Do not merge model/language or destination from Focus into keyboard capture. For ordinary runs freeze global values too; resolvedStopDestination’s no-override path must read the frozen destination for an active run, not a newly changed global setting. Preserve no-active-run legacy behavior and explicit Stop precedence. Automatic stop/interruption uses the same frozen selection. If #1009 is installed, explicit Start/Stop and frozen Focus destinations outrank spoken routing; suppressed commands remain literal. A global destination may still be overridden by an enabled supported spoken command.

Resolve destination before keyboard publication. A Focus history-only run must suppress KeyboardDeliveryPublisher offers, clipboard, shared external preview publication and polish just like explicit history-only. Preserve the existing History/sync distinction: history-only means no external immediate delivery, not necessarily on-device-only storage. Explicit Stop can intentionally redirect that same run; its origin must be carried rather than guessed from a non-nil resolved enum. Keep #994’s single policy writer and #996 recovery receipts.
