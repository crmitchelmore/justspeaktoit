# #1114 implementation plan: shared bounded-memory multipart uploads

Decision: NARROW; SOL medium. This is independent of live folds. Share multipart assembly/upload and retain provider-owned authentication, request fields, decoding and capability checks. Read AGENTS.md, reviews/1114.json and existing #706 staging tests. No six-wrapper deletion, registry rewrite or every-provider adoption target.

## Concrete transport contract

Create `Sources/SpeakCore/OpenAICompatibleBatchTranscriptionClient.swift` (the ticket name is acceptable; document that the transport itself is ordinary multipart). Accept a fully constructed caller-owned endpoint/request or explicit endpoint plus header dictionary, ordered form fields, file field name, filename, MIME type, source file URL, provider staging label and injected URLSession. Prefer small immutable field/file parameter structs if they make the signature readable; no provider registry/protocol framework. Return `(data: Data, response: HTTPURLResponse)` and use existing `TranscriptionProviderError.invalidResponse/httpError` for transport validation. Do not impose Bearer auth, infer an endpoint suffix, decode provider JSON or trim caller credentials inside generic transport.

Use ordered fields, not `[String:String]`, so existing order remains reproducible and repeated field names are representable. Core owns generated multipart boundary and Content-Type, overriding any stale caller multipart Content-Type consistently. Preserve response body text and `<no-body>` fallback in non-2xx errors. Keep provider-specific errors above this layer. New API has no old signature to preserve; leave all existing exported Data helpers and clients source/API-compatible.

Move `Sources/SpeakApp/MultipartUploadStaging.swift` to SpeakCore, removing its self-import. It already depends on core `ReleaseTrain` namespace and `SpeakLogger`, and is not a multipart writer. Expose only the class/initializer/shared lifecycle operations required by current Mac consumers; preserve directory naming, 0700 directory repair, 0600 files, in-process active claims, stale age, filename matching and removal-failure retry. Search all references, including startup cleanup and Mistral/test injection. One shared singleton must own claims after the move; do not leave separate Mac/core claim registries.

Build the body into a claimed staged file using FileHandle. Write small headers/fields, copy input using a fixed chunk size (reuse Mistral's 1 MiB maximum), then CRLF and closing boundary. Never use `Data(contentsOf:)` for the complete recording or build a recording-sized multipart Data. Close both handles on all paths. Reuse Mistral's filename escaping (remove CR/LF, escape quotes/backslashes); reject or safely encode invalid dynamic field/header tokens rather than allow header injection. Preserve normal filenames and exact audio bytes. Cancellation checks between copy chunks keep large staging work interruptible; do synchronous file work away from the UI actor using a bounded task that is awaited, propagates cancellation and cannot outlive cleanup.

After successful construction call `session.upload(for:request,fromFile:)`. Establish cleanup ownership immediately after file creation: partial write/open/read failure removes the partial file, and upload success, network failure, cancellation, non-HTTP and non-2xx outcomes remove it after the network task no longer needs it. Provider decoding occurs after upload cleanup, so decode failure cannot strand audio. Do not delete the original recording. Preserve active claims through the whole upload; stale purge must not remove an old but still-active body. Removal failure is logged without audio/credentials and remains eligible for the existing stale retry. Do not create a broad new disk cache or background upload subsystem.

## Bounded adoption

Migrate `Sources/SpeakApp/OpenAITranscriptionProvider.swift.transcribeFile` first. Preserve endpoint `baseURL/audio/transcriptions`, Bearer key, ordered `model`, `response_format`, optional `chunking_strategy=auto`, optional language field selected by `OpenAITranscriptionModels.batchLanguageFieldName`, then file. Preserve singular/plural language semantics, locale normalisation, audio/m4a, current model extraction, diarised response parsing, speaker labels, duration/cost/raw payload and validation service names. The adapter still builds `TranscriptionResult` with AVFoundation.

`GroqTranscriptionProvider` delegates to that adapter, so it adopts transport automatically. Keep its file, metadata, `https://api.groq.com/openai/v1` base and Groq-specific validation label exactly unchanged. Do not accidentally hardcode the OpenAI host in core.

Migrate `ElevenLabsTranscriptionProvider.swift.transcribeFile` after OpenAI tests pass. Preserve `/v1/speech-to-text`, `xi-api-key` with no Authorization header, `model_id`, `timestamps_granularity=word`, optional `language_code`, filename/MIME and its own response decoder/error/validator. Authentication is the issue sample API's concrete error: a Bearer-only helper is unacceptable.

Move staging without converting Mistral's already streamed body writer in this first patch. Its custom `makeMultipartUploadBody`, filename handling, key trimming, language handling and tests stay intact against the moved lifecycle type. A small follow-up may replace that writer after byte/behaviour comparison, but it is optional. Leave Rev.ai asynchronous job submission/polling and other providers untouched; they are not proven OpenAI equivalents. Keep all Azure, MetaMuse, Speechmatics, XAI, Gemini and Groq wrapper files and metadata. Their capability/validation distinctions have independent value.

In `Sources/SpeakiOS/Services/IOSBatchTranscriptionClient.swift`, remove only the private duplicate Data multipart extension and change calls to existing SpeakCore `appendFormField(named:)` / `appendFileField(named:filename:mimeType:fileData:boundary:)` / `appendString`. This satisfies the reviewed bounded iOS consistency task while keeping its error mapping/decoder intact. Adopting staged upload on iOS can be a later separately tested step; do not claim its current whole-audio memory duplication is removed by helper reuse. Avoid modifying unrelated private Data extensions elsewhere based solely on a grep-zero goal.
