## 2. Transport, framing and lifecycle

Use the upstream narrow fakeable socket/send seam and deterministic timing injection. Retain/inject the init HTTP request task as well: abort/restart must cancel it and prevent its late completion from opening a new socket.

Expose one internal production init-request builder and decoder for tests. Preserve `model = solaria-1` after catalogue routing, trimmed x-gladia-key, JSON content type, wav/pcm, 16-bit, rate/channels, language normalisation (`en_GB` → en; absent language → empty list/code switching). Port every explicit `GladiaMessagesConfig.transcriptsOnly` Boolean from the dedicated client, including disabled acknowledgment/processing/speech events and enabled errors/lifecycle. Do not add paid features. Require successful init status as dedicated code does (201), map 401/403 usefully, reject non-HTTP/malformed/missing URL responses and keep returned single-use URL private.

Frame arbitrary shared/iOS chunks into 100 ms PCM16 frames; preserve final nonempty 50 ms minimum padding as app behaviour. Reuse an already-parameterised internal framer if available; otherwise a small Gladia-local helper is sufficient. Preserve all input bytes/sample alignment and five-second startup suffix cap. Maintain byte counts without rescanning the entire array on each input. One ordered admission/send path drains pending frames before later input; new audio cannot overtake backlog when socket creation races capture. Do not rely on a subsequent microphone chunk to flush startup audio. Keep buffers/send work bounded.

Every HTTP completion, socket receive/send completion, parser, deadline and cancellation captures one session identity. Restart resolves old waiters before reset. Reject post-finish audio. Avoid callbacks/continuation resumption while holding locks. Use session-local accounting, not one mutable global DispatchGroup across recordings.

`finishAndWait` arms shared completion state, flushes residual after controller converter-tail drain, waits admitted audio sends up to 1.5 seconds, receives through configured user grace, then sends exactly `{"type":"stop_recording"}` in order. Bound its send completion. Keep accepting all final utterances through normal server end/close or the configured post-stop budget; a single final or stop acknowledgment must not imply all audio was transcribed. If init is still pending, allow it to finish and send buffered audio within a bounded startup/send stage; timeout cancels the HTTP task and returns available transcript. No new session/retry after abort.

Current primary reference confirms binary audio, stop_recording, confidence, and distinct stop acknowledgment/end_recording/end_session messages. Parse envelope type first so these do not require `data.is_final`. Treat `end_session`/normal terminal close as completion; end_recording or acknowledgment alone is not transcript completion. This is a conservative inference from the separate lifecycle events. [Gladia WebSocket reference, checked 12 September 2026](https://docs.gladia.io/api-reference/v2/live/websocket).

On deadline/error, preserve finalised text plus outstanding interim. No final consumed by finish is also delivered through final transcript callbacks. Emit its standalone boundary once via the explicit boundary capability, after its corresponding state update; generic finish adoption must not emit another full-history boundary. Maintain mean-confidence segments including late finals. `stop()` is prompt abort, resolving every finish caller once. Repeated/concurrent finish joins one operation. Bound total legitimate grace/send/final time below the manager's ten-second stop safety timeout; do not conceal timeout/failure as proven tail delivery.
