# #963 implementation plan: Stop in the small Live Activity

Decision: IMPLEMENT, SOL medium. Add an accessible Stop control and optional Double Tap primary action to the existing iPhone Live Activity’s small presentation. No native Watch recorder activation, relay transport, Start/Toggle, new intent or payload fields. Read reviews/963.json and the refined issue body; coordinate the shared widget file with #945/#1001 and retain #932’s activity/run isolation. Additive code and a draft can proceed now; physical wrist-stop evidence remains mandatory before claiming the feature works.

## Verified API and availability contract

On 12 September 2026, Apple’s published DocC JSON metadata confirms iOS/iPadOS 18.0 availability for `WidgetConfiguration.supplementalActivityFamilies(_:)`, `EnvironmentValues.activityFamily` and `View.handGestureShortcut(_:isEnabled:)`. Sources are the corresponding paths under https://developer.apple.com/tutorials/data/documentation/swiftui/ ending in `widgetconfiguration/supplementalactivityfamilies(_:).json`, `environmentvalues/activityfamily.json` and `view/handgestureshortcut(_:isenabled:).json`. No local Apple SDK headers were available; verify declarations and actual compilation on the supported Xcode SDK before merge.

Apple’s [WWDC24 Live Activity guidance](https://developer.apple.com/videos/play/wwdc2024/10068/) shows the supplemental `.small` family and environment-based layout with the medium presentation retained; it requires no Watch app. [WWDC24 watchOS guidance](https://developer.apple.com/videos/play/wwdc2024/10205/) demonstrates a visible button’s `.primaryAction` gesture. Current [custom Live Activity guidance](https://developer.apple.com/documentation/ActivityKit/creating-custom-views-for-live-activities) also covers small presentation in CarPlay. Treat `.small` as a layout size, never as a device identity or proof of Watch-only privacy. Do not add CarPlay interaction promises; keep this view appropriate for incidental display there. No iOS 27 width API or deployment-target increase is needed.

## Exact source changes

Work primarily in `JustSpeakToItWidgetExtension/JustSpeakToItWidgetExtensionLiveActivity.swift`. Its existing `JustSpeakToItWidgetExtensionLiveActivity.body` constructs one ActivityConfiguration; LockScreenTranscriptionView serves content and the Dynamic Island closure is separate. Preserve the single widget registration and existing Dynamic Island/medium behavior.

1. Factor the existing configuration into a private reusable configuration property/helper if necessary. At the WidgetConfiguration level, use an iOS 18 availability branch to apply `.supplementalActivityFamilies([.small])`; on iOS 17 return the unmodified configuration. Use the SDK-supported WidgetConfiguration builder for conditional opaque results, not a View modifier or AnyView around a WidgetConfiguration. Compile this small scaffold first on Apple. Do not duplicate the entire Dynamic Island closure or create two registered widgets to satisfy availability.
2. In the content closure, select an iOS 18-only private `TranscriptionActivityFamilyContent` view; its `@Environment(\.activityFamily)` property belongs inside that availability-annotated type. Its `.small` branch renders `SmallTranscriptionActivityView`; `.medium` and unknown future values render the current LockScreenTranscriptionView. The iOS 17 branch renders that same LockScreen view directly. Merely guarding body access is insufficient if an unguarded stored environment property still references the new API.
3. Keep both content variants under the existing release-aware transcribe widget URL. Do not alter deep-link handling, Watch launch Info.plist keys, activity creation/update frequency, expiration or eligibility. No edits to Project.swift flags, Watch signing/provisioning or Native Watch files are required.
4. Implement the small view with one status icon, concise status text and, only when eligible, a visible `Button(intent: StopTranscriptionRecordingIntent())` labelled “Stop”. Use a native button style, semantic text colors and a minimum 44-point hit target within the available card. Apply `.handGestureShortcut(.primaryAction)` to that button itself; it is the sole primary action in this presentation. Keep ordinary tapping functional. Do not place an invisible shortcut on a container or reuse a hidden/disabled Start button. The existing native Watch `primaryActionGestureShortcut` helper is a pattern, not a shared module to import.

## State and privacy behavior

Read the current enum in Sources/SpeakCore/TranscriptionActivityAttributes.swift. Render every current case explicitly:

| Status | Small text | Stop/gesture |
| --- | --- | --- |
| recording | Recording | One enabled Stop |
| listening | Listening | One enabled Stop, matching existing eligibility |
| arming | Preparing… | None |
| armed | Ready for speech | None |
| idle | Ready | None |
| paused | Paused | None |
| finalising | Finishing… | None |
| processing | Processing… | None |
| error | Needs attention | None |
| completed | Existing resolved outcome message | None |

For completion, reuse `TranscriptionResultRow(state:).outcomeMessage` from SpeakCore. It derives the already-resolved completion outcome; never replace it with a universal “Copied” or “Saved” promise. If a future state cannot provide a result row, use neutral “Finished”. Allow two lines/appropriate dynamic layout rather than changing outcome semantics to fit. Error text is a neutral status only because startup and provider failures do not prove a recording interruption: do not copy errorMessage or lastSnippet, which can contain private or provider-specific details.

The small view contains no transcript preview, result snippet, raw error, provider/account details, Copy/Open action or timer. In particular do not use `attributes.startTime` as recording duration: it can describe an older primed card. Leave richer existing medium result actions and preview behavior intact; their redesign belongs to #1001. A result with no active recording has no enabled gesture even if stale non-empty snippets or previews remain in the payload.

## Preserve Stop ownership and delivery

Reuse `Sources/SpeakiOS/Activity/TranscriptionIntents.swift`’s existing iOS 18 `StopTranscriptionRecordingIntent` with no destination override. Preserve AudioRecordingIntent/LiveActivityIntent conformance, alwaysAllowed authentication, app-process execution, keyboard-owned finish path, explicit/current-run/settings destination precedence and receipt-driven dialog. Its foreground-owner refusal remains correct: a wrist interaction cannot seize a recorder owned by the app’s separate foreground coordinator.

Do not show optimistic completion when the user taps; rendered status follows the existing ActivityKit updates. Never add a new direct call to a widget-process service singleton, WatchConnectivity message, forced owner release or fallback Start. Existing intent/run checks own repeated or stale calls. If physical rapid-restart evidence reveals a stale action ending a newer run, retain that trace and coordinate #932/owner policy before adding parameters or changing public intent semantics. Current tests cannot establish remote delivery timing.
